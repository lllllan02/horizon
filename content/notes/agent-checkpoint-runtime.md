实现[[agent-checkpoint-recovery|中断恢复]]，先确定检查点的保存位置，再保存足以驱动后续执行的数据。

## 检查点放在哪？

在[[agent-loop|Agent Loop]]中，可以按一次完整的模型或工具调用设置保存边界：

- 模型完整返回后、执行工具前：保存模型响应，恢复时复用已经确定的工具名和参数。
- 每个工具返回后、再次调用模型前：保存对应结果，恢复时跳过已经完成并保存结果的工具。

首次调用模型前先保存用户输入；主动暂停时保存等待事项；得到最终回答后保存回答与完成状态。多个工具分别保存完成结果，才能逐个复用。

每次把结果和下一步一起写入持久存储，保存成功后再继续。中断发生在保存之前，这次调用仍可能需要重做。

## 保存什么信息，才能继续恢复？

判断标准是：新进程读回记录后，能否知道下一步做什么，并拿到所需输入。

| 保存的信息 | 至少包含什么 |
| --- | --- |
| 任务身份与执行位置 | 稳定任务 ID；下一步是调用模型、执行工具、等待输入还是返回回答 |
| 模型输入与响应 | 用户输入、必要消息历史、完整模型响应，包括最终回答 |
| 待执行工具请求 | 原调用 ID、工具名、确定的参数，以及尚未执行的请求列表 |
| 已完成工具结果 | 与原调用 ID 对应的结果或错误，供后续模型调用直接复用 |
| 等待与结束信息 | 等待项 ID、继续条件及收到的决定；完成、取消或过期状态 |

这些运行信息由程序依据实际执行结果更新。[[agent-task-state|任务状态]]中的目标、待办和判断可以一同保存，但恢复程序需要明确的执行位置与原始调用数据，不能只凭「下一步继续处理」这样的描述接续。

外部写操作还应保存稳定操作 ID，供恢复时查询结果或依赖远端幂等保证重试；本地未保存结果，不足以证明远端没有执行。
