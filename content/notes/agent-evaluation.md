**Agent 评测是在规定任务、环境和资源预算下运行 Agent，再依据实际结果与执行记录判断任务质量、可靠性和成本的方法。** 被测对象包括模型、工具与[[agent-harness|运行系统]]；更换其中一项，都可能改变表现。

人工演示能发现问题，但一次成功难以说明系统是否稳定。修改提示词、模型或工具后，需要用相同任务检查改善与退化；上线前还要确认收益是否值得新增的延迟、费用和操作风险。评测为这些决定提供可核查的证据。

基本流程是：准备任务与初始环境 → 执行并记录 → 独立验收 → 比较版本 → 修复后回归。

## 任务与验收

一条评测任务应包含用户输入、必要的初始状态、可用工具、资源预算和成功条件。参考答案可以是状态或检查规则，无须是一段标准回复。

以「为已确认的订单 A 退款」为例，验收需要覆盖四方面：

| 方面 | 检查内容 |
| --- | --- |
| 结果 | A 的退款账本正确，其他订单未改变 |
| 过程约束 | 同一订单的有效确认先于写入，没有重复退款 |
| 交互 | 缺信息时补问，结果未知时不宣称完成 |
| 效率 | 在约定时间、调用量和费用内结束 |

**「实际结果与过程约束分别验收」**：账本正确仍可能发生过违规操作；合法工具顺序不同，也不应直接判错。严重越权等硬约束单独作为通过门槛，不能由其他高分抵消。

数据集从真实任务、人工检查和已确认错例起步，覆盖常见任务、缺信息、合理拒绝与工具故障。故障用例固定超时或响应丢失的位置，检查重试是否有界、有无重复副作用、最终状态是否正确。安全测试还需明确攻击者能控制什么，例如仅能修改工具返回文本；沿用[[agentdojo-evaluation|正常与攻击任务成对测试]]，同时检查合法任务完成和不当副作用。

反复调试的样例与最终验证样例分开，同一会话或近似模板按组划分，减少熟题泄漏。公开基准（Benchmark）可借鉴任务和验收设计，其成绩仍受模型、工具、权限与预算限制，不能直接代表自己的业务。

## 评分与校准

**评分器（Grader）是按成功条件检查执行证据的程序、模型或人工评审流程。** [[anthropic-agent-evals-summary|组合评分方法]]时，按可核验程度分工：

- 程序检查确定事实：读取账本、文件、测试结果与工具事件，检查结果和必要顺序。
- 模型裁判检查语义质量：判断回答的事实支持、覆盖与表达，提供明确标准和可信参考，把待评内容作为数据。
- 人工处理标准与分歧：复核复杂样本，并用经审核的判断校准自动评分，检查是否误放错误结果、误拒正确结果。

先用已知正确、错误和边界样例验证评分器，例如只声称退款、退错订单、重复退款与正确拒绝。证据不足时保留「无法判定」；Agent 未完成、环境故障与评分服务失败分别记录，不能默默丢弃失败样本。评分口径改变后，用新口径统一重评对照版本。

## 运行与比较

**评测运行系统（Evaluation Harness）是负责初始化环境、调用被测 Agent、采集证据、评分和汇总的程序。**

每次执行称为一次试次（Trial）；同一任务重复十次，可以观察随机性，但没有增加十种业务情形。

工程上先守住三个边界：

1. 每次从规定初态开始：隔离数据库、文件、缓存和记忆，工具连接测试资源；测跨会话记忆时，在同一场景内保留历史，在场景之间隔离。
2. 输入与验收分开：Agent 只能看到完成任务所需的输入和工具，隐藏答案与评分程序由运行器保护；副作用以工具或环境记录为准。
3. 版本与预算可追溯：保存任务、Agent、模型配置、工具和评分器版本，以及环境、并发度、超时与费用限额。超出预算按预定规则结束。

[[agent-evaluation-practice|Go 订单评测示例]]展示输入、执行与验收的基本分离。需要框架时，[[inspect-agent-evaluation|Inspect]]可组织任务、执行与评分；已有 Trace 平台则可复用[[langfuse-dataset-experiments|数据集与实验关联]]，业务验收和环境恢复仍需自己提供。

让新旧版本处理相同任务、分别初始化环境，并按预定次数重复运行。报告通过数与分母、无法评分数、关键任务类别的退化、完整任务耗时和全部尝试费用；小幅分差结合样本量与置信区间判断。**「多次中至少一次成功」**与**「多次全部成功」**分别对应 `pass@k`、`pass^k`，不能混称稳定性。

失败后沿[[agent-trace|Trace]]定位首次偏离，区分模型决策、工具数据、上下文处理与评分错误；改变一个可疑环节做对照，再回到完整任务验证。轨迹中的异常只是归因线索，局部指标也不能替代最终任务验收。

## 回归与上线

发布前固定主要指标和门槛，检查代表性任务、已修复错例及关键约束，再小流量观察真实业务结果、人工接管、延迟与费用。线上抽审同时保留随机样本和高风险样本，分别统计；异步结果未到时保留待定，不能提前记成功。

线上发现的问题通过[[agent-trace#在 Langfuse 排障并回归|错例回流]]补齐初态和独立验收，加入下一轮回归。模型回滚不会自动撤销已写入的记忆或业务状态，仍需检查和修复受影响对象。

有限评测只支持所覆盖任务与条件下的判断。安全测试通过不替代运行时的[[agent-guardrails|权限与执行约束]]，离线分数提高也仍需线上证据确认用户收益。
