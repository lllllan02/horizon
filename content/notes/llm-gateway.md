**大模型网关是位于应用与模型服务之间，统一接入并治理模型请求的服务入口。**

当多个应用接入不同模型时，分别维护供应商协议、密钥、路由和额度会产生重复工作。网关把这些共用规则集中执行，让应用通过相对稳定的接口调用模型；代价是增加一层转发与运维责任。只有少量简单调用时，直接接入也可以满足需求。

## 放在系统的哪里？

![[assets/llm-gateway-position-v2.png|640]]

网关接收请求，检查身份与规则，选择上游并转换协议，再转发结果和记录用量。普通 API 网关的鉴权、代理与流量控制仍是基础，大模型场景还要处理流式生成、模型能力差异与 Token 用量。

[[agent-harness|Agent Harness]]负责组织上下文、执行工具和推进任务；网关负责其中模型调用的接入与治理。推理服务执行模型计算，网关的职责本身不包含训练或 GPU 调度。这些职责可以集成在同一产品中，概念上仍应区分。

网关还要区分「**请求执行与配置管理**」：前者处理每次调用，后者维护模型、上游和策略；二者不一定部署为独立进程。[[llm-gateway-sources#职责与配置边界|官方架构资料]]提供了这种分工的实例。

## 按什么顺序学习？

**基础概览 → 机制理解与小实验 → 成熟项目源码。** 先用前三篇建立整体认识：

1. [[llm-gateway-request|请求链路]]：先弄清应用、网关与上游之间的请求和响应怎样流转。
2. [[llm-gateway-characteristics|大模型请求的特殊性]]：理解长流、未知输出长度与能力差异带来的约束。
3. [[llm-gateway-governance|治理能力]]：再看权限、流量、故障、计费、缓存与观测分别解决什么问题。

### 机制学习与小实验

每次先讲清一项机制的正常与失败过程，再用可控模拟上游验证。各实验可共用一个支持普通响应与 SSE 的 Go 最小代理；[[llm-gateway-sources#流式转发与失败边界|Go ReverseProxy]]可作参考。以下是待讨论问题与实验建议，机制尚未逐项展开，实验尚未执行。

| 顺序与方向 | 接下来要讲清的问题 | 对应的小实验 |
| --- | --- | --- |
| 1. 流式生命周期与协议适配 | 网络读取怎样组成事件？请求、响应、错误与用量怎样转换？正常结束、断流和取消时怎样收尾？ | 分别模拟普通 JSON、分片 SSE、断流和客户端取消。 |
| 2. 路由与失败恢复 | 怎样筛选模型和渠道、分配请求？首段前失败与部分输出后失败，分别能否重试或换渠道？ | 双上游模拟超时、429 和断流，核对每次选择与调用尝试。 |
| 3. 准入、流量与容量 | 请求速率、Token 速率、在途并发和总额度何时检查、更新？队列满或输出超出预估时怎么办？ | 先验证单实例并发上限与有界等待，再加入长输出和额度临界场景。 |
| 4. 用量记录与结算 | 请求、尝试、用量与收费怎样关联？预留何时释放或结算？用量缺失、重复或写入失败时怎样处理？ | 核对成功、重试和用量缺失的记录，再检查重复事件与取消。 |

**鉴权、租户隔离与基本观测贯穿四项**：明确调用方和上游密钥的归属，用请求标识关联尝试、状态、耗时与用量。Agent 的[[agent-trace|执行追踪]]可作对照，模型生成重试仍需单独判断。

单项机制清楚后，再组合取消、重试与额度，检查资源释放和残留预留；测量时区分代理开销与模型延迟，并保留负载和环境条件。

### 成熟项目与源码

选择一个项目，固定版本或提交，追踪一条正常请求与一条失败请求，再做一项有测试支持的小改动。下面是不同入口，不是必须依次学习的三套产品；[[llm-gateway-sources#项目与代码入口|官方实现资料]]保留定位与版本条件。

| 项目 | 适合跟踪的主线 |
| --- | --- |
| New API | 用户与令牌 → 模型和渠道 → 协议适配 → 额度与消费记录，适合模型 API 平台二开 |
| APISIX | 路由与插件阶段 → AI 代理 → 限流、缓存及配置生效，适合网关扩展与流量治理 |
| LiteLLM | 统一模型接口 → 虚拟密钥 → 路由、预算与日志，可作为功能和设计对照 |

### 按需延伸

- **缓存正确性**：有复用需求时，讨论匹配条件、租户隔离、不完整流与命中后的用量口径，再比较语义缓存和供应商提示缓存。
- **配置管理与恢复**：需要动态调整模型、渠道、密钥或策略时，讨论校验、生效、发布与回滚。
- **多实例一致性与容量验证**：单实例机制明确后，再按规模讨论共享配额、记账一致性、依赖故障、高可用与压测；不预设完整分布式平台。

更完整的权限模型、敏感数据保护和指标／Trace 采集，随多租户服务与线上排障需求加深。岗位能力可结合[[lingtong-llm-gateway-preparation|网关岗位准备清单]]自查。
