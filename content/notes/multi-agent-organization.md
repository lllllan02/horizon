**多 Agent 的协作方式，规定任务由谁分配、信息怎样交换，以及结果和冲突由谁处理。**

独立任务通常只需交回成果；中间发现会影响其他成员时，就需要执行中的协调。

![[assets/multi-agent-collaboration-modes-v2.png|640]]

1. **任务委派**：父 Agent 通过[[langchain-multi-agent#具体怎样实现？|工具等接口调用子 Agent]]，交代目标、上下文和输出要求；子 Agent 独立执行并返回成果，由父 Agent 验收、决定下一步。
2. **执行中协作**：成员持续交换进度、阻塞和发现。有主管时由主管调整分工、汇总结果；无固定主管时，成员通过共享任务或直接消息协调，事先约定认领、汇总和裁决规则。共享任务板不等于主管 Agent，[[claude-code-agent-collaboration#何时改用团队？|有主管也可以成员直通]]。

**委派也可以并发，两种场景可以组合。** 子 Agent 不要求对应新协程、进程或不同模型；[[autogen-group-chat|轮流发言的群聊]]也不等于并发。路由负责选择执行者，交接则让下一角色接管。

[[eino-multi-agent|Eino 源码导读]]沿对象、方法调用、消息数组和检查点，说明子 Agent 怎样被管理、交接结果和恢复。

通信由程序完成：**同一进程内**可直接调用，或用内存队列、Channel；**跨进程**可用消息队列、HTTP、gRPC。[[a2a|A2A]]统一跨服务交互约定，由 HTTP 等承载，也可包装成工具。

消息通常带任务标识、收发方、类型和内容，大产物可传存储地址。[[agent-harness|运行系统]]收到后更新状态，需要模型判断的内容再加入上下文、继续执行。**消息送达不代表模型已处理。** 依赖未到就保存进度等待；超时先查状态，只重试安全步骤，取消后检查剩余运行和迟到结果。

共享资源的边界需要另外约定，不能靠消息通信自动解决：

- **结果分歧**：先交换冲突位置、依据和建议。委派由父 Agent 验收，有主管时由主管裁决、要求补查或重做；无主管时限轮数或时间协商，仍未解决就记录阻塞，交第三方或人工处理。
- **并发依赖**：独立工作可以并行，依赖另一分支的步骤要等待。用[[agent-task-state|任务状态]]记录负责人和结果，程序防止重复认领，并[[concurrency-control|限制并发]]、嵌套和预算。
- **同文件修改**：优先分开文件；必须共改时，可约定「**同一阶段只有一个实际写入者**」，其他成员交修改建议，由负责人读当前版本、整合并验收。已冲突就先停写、核对各方改动，避免继续覆盖。[[claude-code-agent-collaboration#怎样避免文件冲突？|认领任务不等于锁住工作文件]]。

协商上限由程序执行，超限后记录未解决事项并升级；[[mast-multi-agent-failures|停止讨论或意见一致]]都不能代替结果验收。
