**慢查询排查是结合请求耗时、语句记录、执行计划和等待信息，定位数据库请求延迟来源的诊断过程。** 扫描很多行、等待锁、等待 I/O，以及应用尚未取得连接，都可能表现为「查得慢」，需要用不同证据区分。以下以 MySQL 8.4、InnoDB 为范围。

## 先确定慢在哪一段

应用记录取得连接前后的时间、查询调用返回和结果读取结束的时间，避免把[[db-connection-pool|连接池排队]]全算进 SQL 执行。服务端执行、网络传输和客户端读取可能重叠，不能把应用与数据库计时直接相减就认定差额全是网络耗时。保存慢请求的 SQL、实际参数、连接 ID、发生时间和并发情况；参数分布不同，同一种 SQL 也可能产生不同工作量。

慢查询日志（Slow Query Log）记录满足阈值与其他日志条件的语句，可用 `Query_time`、`Rows_examined`、`Rows_sent` 找到候选。扫描多、返回少提示存在可减少的工作，但计数不包含引擎内部全部处理；慢日志也不是完整的等待追踪，具体口径见[[mysql-performance-diagnostics#慢日志记录了什么|官方慢日志说明]]。

## 选择要排查的语句

Performance Schema 是 MySQL 收集语句、阶段和等待等运行事件的监测设施。

sys Schema 是辅助解释 Performance Schema 数据的一组视图、过程与函数；排查时可先用它的视图阅读汇总结果。

`sys.statement_analysis` 按规范化 SQL 汇总次数、总耗时与平均耗时。排查目标决定先看什么：正在阻塞业务时先保存当前请求与等待依赖；接口长尾高时取回对应慢请求及参数；实例总体负担高时比较同一窗口的执行频次、累计耗时与处理量。

例如每次一百毫秒、执行一万次的查询，累计耗时可高于偶发的十秒查询；但后者仍可能直接影响重要请求。这个算例说明累计负担与单次体验是两个判断维度，不代表 CPU 使用量。[[mysql-performance-diagnostics#语句指纹怎样找出累计负担|语句指纹、样本与分位数]]能帮助筛选，具体原因仍须回到同一次执行。

## 从语句找到原因

先用[[mysql-statement-tracing|语句与等待追踪]]确定目标线程和事件，再按观察分支核对；已经结束的请求只能使用事先保留的历史证据。

| 观察到的现象 | 用什么继续核对 | 对应处理方向 |
| --- | --- | --- |
| 扫描多、过滤后剩很少，或内层循环很多 | [[mysql-query-plans\|EXPLAIN ANALYZE]] 对照扫描、过滤和连接节点 | 按[[mysql-query-optimization\|查询优化]]减少候选、取行或重复匹配 |
| 请求被其他事务或 DDL 阻塞 | 按[[mysql-lock-waits\|锁等待排查]]分别查数据锁与元数据锁依赖 | 找到持锁事务，检查事务时长与访问顺序；阻塞连接当前无 SQL 也可能持锁 |
| CPU、文件 I/O 或临时存储活动增加 | 按[[mysql-query-resources\|查询资源排查]]对齐语句工作量、线程证据和系统指标 | 减少对应计算、读写或中间结果，处理共享资源竞争；全局计数不能独立归因到一条 SQL |
| 应用耗时明显高于服务端记录 | 连接池等待、结果量、网络和应用消费时间 | 按发生位置处理排队或传输；先查连接被谁长期占用，再调整容量 |

等待表反映观察时刻，问题结束后可能已无记录；统计视图也受采集配置和历史容量限制。[[mysql-performance-diagnostics#怎样理解汇总与采集边界|采集与汇总规则]]决定了「没查到」能说明什么，不能据此认定从未发生等待。

同一 SQL 从快变慢时，还应区分参数或数据规模变化、[[mysql-query-plans#同一 SQL 为什么从快变慢|计划变化]]与计划相同但等待增加，分别选择下一条证据；不要先假定索引失效。

## 改动后怎样验证

围绕已找到的原因一次验证一项假设：保持数据、参数、并发和缓存条件可比，确认对应的扫描、循环或等待确实减少，再看应用端平均与高分位延迟、吞吐和错误率。

累计统计应比较同一观察窗口内的增量。例如某指纹执行次数从 1000 增到 1100，总耗时从 50 秒增到 58 秒，窗口平均耗时是 `(58-50)/(1100-1000)=0.08 秒`，不能相减两个累计平均值；最大值和 P99 也不能这样作差。

若假设是锁阻塞，改后应看到对应等待减少；若假设是扫描过多，应看到代表性参数的扫描或循环减少。只有再次执行变快、而缺少这些对应变化，仍不能排除缓存或负载变化。EXPLAIN ANALYZE 会实际执行查询，可在受控环境复现，但一次复现不能还原故障时的竞争情况。以上算例为推演，未连接实例执行诊断或性能实验。
