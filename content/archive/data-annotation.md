**在机器学习与 Agent 开发中，数据标注是按照明确的任务规则，为一条数据补上答案、类别、位置或质量判断的过程。** 这些信息可以用来训练模型，也可以用来检查系统做得对不对。这里的数据可能是一句话、一段回答，或 Agent 完成任务的整段记录。

例如原始数据只有「订单 A 能退吗」，标注后增加「意图：查询退款资格」。填写这个判断的动作叫标注，填进去的类别叫标签；原始输入与标注结果放在一起，就形成一条带标注的样本。

## 为什么有了数据还要标注？

收集到用户说过什么，还没有明确告诉训练程序「希望模型把它判断成什么」。同样出现「退款」，「能退吗」与「帮我退」可能分别表示查询和申请；只有文字，没有这层业务约定，程序就缺少学习该分类任务的目标。

标注把约定落实到具体样本上。[[intent-text-classifier|意图分类器]]训练时拿预测类别与标注类别比较，再调整参数；评测时则把系统预测与留出的参考答案比较，统计错误。**标注负责准备依据，训练负责调整模型，评测负责检查表现。** 单纯保存标注文件不会让运行中的 Agent 自动学会它。

[[aws-data-labeling|AWS 的标注说明]]还展示了图片框选、像素区域和语音文字等形式；所以「标签」不一定只是一个分类名称。

## 在 Agent 材料里，具体会标什么？

下表使用自拟订单场景。每行都要先明确任务，再决定补充哪种信息；无需为每条数据填写所有字段。

| 要解决的问题 | 待标注的数据 | 补充的标注 |
| --- | --- | --- |
| 用户想做什么？ | 「订单 A 能退吗」 | 意图：查询退款资格 |
| 句中哪个部分是订单号？ | 同一句话 | 将字符「A」所在片段标为订单号 |
| 合适的回复怎么写？ | 请求及已核实的订单状态 | 写一份符合条件的示范回答 |
| 两个回答哪个更好？ | 同一请求与候选回答甲、乙 | 甲优于乙，并记录比较依据 |
| 检索结果能否支持回答？ | 问题与退款规则片段 | 相关、部分相关或不相关 |
| Agent 哪一步出了问题？ | 请求、工具调用和实际结果 | 将未经请求直接提交退款的那一步标为错误操作 |

前两种是[[rasa-intent-classification|意图与实体标注]]：意图针对整句话，实体针对其中的片段。示范答案提供「希望怎样回答」；偏好标注提供「这几份回答中更认可哪个」。[[instructgpt-human-feedback|InstructGPT 的人工反馈方法]]分别用它们进行监督微调和训练奖励模型。偏好胜出只表示相对更好，两份回答也可能都不合格。

执行轨迹指 Agent 一次任务中的消息、工具调用、工具返回等记录。轨迹标注可以判断某一步是否正确，也可以判断最终任务是否完成。[[anthropic-agent-evals-summary|Agent 评测方法]]强调核对实际状态：Agent 说「已退款」只是一句输出，是否真的退款还需要工具结果或业务记录作证。

## 标注者实际怎样完成一条标注？

下面是根据这些资料归纳的教学流程，未运行真实标注项目。以区分「查询退款资格」和「提交退款申请」为例：

1. **写规则。** 询问能否退款归为查询；明确要求办理归为申请。写出正例和易混反例，例如「别退款，先查能不能退」应归为查询。
2. **提供数据与必要上下文。** 标注者看到待判断的原文；「那就退吧」还需要前文才能理解。缺少关键上下文时允许记录「无法判断」。
3. **作出判断并保存。** 选择类别，必要时附上理由与证据。实体任务需要选中文字范围；示范任务则需要写答案。
4. **复核分歧。** 让另一位标注者独立判断部分样本。意见不同时检查漏读、证据缺失或类别定义重叠，再修正规则或结果。
5. **按用途交付。** 同时保存数据编号和规则版本。训练、调参和最终测试使用分开的数据；相同会话或近乎重复的模板不应跨组造成答案泄漏。

一条结果可以保存在表格的一行里，也可以保存成 JSON。下面的字段是教学示例，没有统一强制格式：

```json
{
  "id": "example-001",
  "text": "订单 A 能退吗",
  "intent": "refund_eligibility",
  "reason": "只询问资格，没有要求办理退款",
  "guideline_version": "v1"
}
```

英文类别值只是约定的名称。标注平台主要帮助展示样本、选择或填写结果、分配复核和导出文件；小规模任务也能用表格完成。决定结果含义的是任务规则。

## 谁来标？标出来就算正确吗？

标注可以由人完成，也可以由规则或模型先产生候选，再由人审核。人工适合需要业务知识和处理争议的样本，程序适合能直接核验的字段与状态，模型可辅助大批语义判断；具体分工取决于错误代价与可核验程度。

**被保存成标签的判断仍可能出错。** 常见问题包括：规则含糊、上下文缺失、标注者理解不同、模型重复产生同一类偏差。多人一致也可能一起理解错，所以还需要核对原始证据，而不只统计一致率。

Ground Truth（参考真值）或 Gold Label（金标准标签）通常指任务中采用的可信参考答案，不代表永远不会错。发现错误后，应修正并记录版本；否则模型原本答对，也可能被错误参考判为失败。[[agent-evaluation#评分与校准|模型裁判校准]]就是把自动评分与经过复核的人工判断作比较，检查裁判能否可靠执行同一套标准。

## 怎样分清标注、预测和训练？

模型对新请求输出一个意图，通常叫预测；把这个结果收集起来，作为其他训练或评测的参考数据时，它才承担自动标注的角色，仍需质量检查。两者可以输出相同的文字，区别在用途与验证方式。

调用现成模型开发 Agent，不必先自己标注大规模训练集；少量经过复核的标注样本也可以专门用于回归评测。语言模型预训练中的「预测下一个词元」则能从原始文本自动构造目标，不要求人逐字填写答案。

阅读时可以用四个问题定位含义：**给什么数据标、填写什么结果、依据什么规则、结果用于训练还是评测？** 若材料谈的是代码类型注解、工具描述或文档批注，则是 annotation 的其他用法，不能直接套用数据标注的含义。
