**长期记忆写入是从交互与执行结果中，提取未来仍有用的信息，形成带条件和依据的记录的过程。** 不要求每次交互都产生记忆。

## 原文要全部保存吗

[[history-storage|原始历史]]按回查需要保存，长期记忆从中筛选可复用内容。两者可以并存：记忆保存结论和来源，需要细节时回查原文；必须准确复现的约定可直接保留原始片段。聊天摘要也可能包含临时细节，不能直接当作长期记忆。

## 什么信息值得长期记住

判断标准是：**「未来什么任务会用到它？它能改变做法、减少重复询问，或避免已知错误吗？」** 常见候选包括：

| 内容 | 值得保留的部分 |
| --- | --- |
| 偏好与约束 | 明确的长期要求、有依据的重复习惯及适用范围 |
| 持续相关的事实 | 会影响后续工作的项目结构、环境限制、对象关系 |
| 目标与决策 | 仍有效的目标、已确认的选择及原因 |
| [[agent-memory#写入\|可复用经历]] | 任务条件、采取的行动、实际结果和限制 |

每条候选都要核对用途、依据和范围。明确的长期要求，一次即可记住；单次请求与原因猜测不能直接推广。低频但关键的限制也应保留，[[memorybank-memory|回忆频率]]不能代替重要性与正确性判断。有截止日期的约定同样可以跨会话复用。

## 怎样从原话提取

[[codex-memory-pipeline|提取与整合]]可归纳为三步：

1. 拆出候选：分别识别事实、要求、决策和经历，去掉寒暄与重复过程。
2. 核对证据：区分用户表达、助手建议和实际验证，确认对象与期限；不足以支持的结论暂不写入。
3. 形成记录：保留结论、条件与来源，不把项目要求扩成全局偏好。

![[assets/agent-memory-extraction.png|长期要求提取为有范围和来源的记忆，本次要求只用于当前任务]]

多次交互可以形成[[generative-agents-memory|概括]]或[[a-mem-memory|条目关联]]，但推导不能冒充原始事实，同一来源的多次转述也不算独立证据。

## 提取后怎样更新

按同一用户、项目与属性比较旧记录：重复则不新增，互补则补充，明确纠正则更新，范围不同则分开；冲突不明时保留待确认。[[mem0-paper-memory|论文机制]]与[[mem0-memory|产品接口]]的更新语义需分别核对。

程序校验来源和版本后提交，防止旧任务覆盖新纠正；到期、纠正或删除时，同步处理派生摘要与索引。最后用新会话检查能否复用、是否越界，以及旧值是否仍影响回答。
