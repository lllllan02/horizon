**索引维护要让原文变化沿着片段、向量、摘要与缓存传播，并保证查询能识别当前有效版本。** 仅重新写入向量，会留下旧片段或旧答案。

## 更新怎样保持同一文档身份？

文档保留稳定 document_id，每次内容变化产生新 version。处理程序比较内容 hash 与处理配置：未变化的内容可跳过，变化的文档重新解析和切分，再生成新片段。即使原文未变，切分器或 embedding 版本改变也可能要求重建。

[[llamaindex-document-management|LlamaIndex 的更新与刷新接口]]提供按文档 ID 维护的原语。应用仍需确保旧版本多出来的片段被移除；仅 upsert 当前片段无法删除已经消失的段落。

## 怎样避免查询读到半个版本？

一种自拟方案是「构建新版本 → 验证完整性 → 切换 active_version → 清理旧衍生物」。构建和当前查询分开，失败时继续服务完整旧版本；同一请求绑定一个快照，回取原文时保持相同版本。

单库可利用事务协调状态，跨多个后端则需要发布标记、幂等写入和补偿检查。不能假定关键词索引、向量库与对象存储天然同时提交。记录处理版本，使重试不会重复发布不完整结果。

## 删除与撤权有什么不同？

删除资料需要传播到片段、向量、摘要和依赖这些资料的缓存。撤销某个用户权限则未必删除文档本身，但必须立刻阻止该用户继续读取，缓存命中也不能绕过检查。

可先在查询权威状态中标为不可用，再异步清理衍生物，并对重试与完成状态做核对。旧索引延迟返回的 ID 还须经过当前授权与有效性校验。[[rag-security-docs|OWASP 的衍生数据说明]]强调了只删除源文件留下向量的风险。

## 模型迁移怎样验证？

新 embedding 与旧索引分开构建，影子查询比较证据质量、过滤后召回与延迟，确认后切换；保留可回滚配置并限定旧数据保留时间。回滚不应恢复已撤销权限。验收至少包括新增、修改、删段、整文删除、撤权和迁移中查询。
