**协作流程把共同目标推进为最终交付，包含分工、执行、成果汇合与必要的反馈。** 各成员完成子任务以后，还需有人或程序检查它们是否共同满足用户要求。

下面是一种教学设计：用户要求「比较三个候选方案，给出适合当前项目的建议，并注明依据」。采用[[multi-agent-orchestration|主管委派与并行分工]]，汇总与审查依次进行。

1. **明确共同目标。** 主管整理项目约束、比较标准与最终交付要求。先确定什么算完成，再决定是否拆分及需要哪些成员。
2. **划分任务并约定交付。** 三个调查者各负责一个方案，收到相同的项目约束和比较标准，返回事实、出处、不确定项；主管负责汇总，审查者负责检查。任务说明还要约定工具与操作范围、预算及停止条件。
3. **推进能够开始的工作。** 调查者分别查证。某个分支失败时返回失败原因与已完成部分，主管决定重试、改派或保留缺口；依赖该成果的比较暂不能视为完成。
4. **汇总并处理分歧。** 主管核对各分支是否比较了相同条件，再形成建议。若两个结论冲突，先检查版本、条件与出处，必要时定向补查，回到相关调查分支。
5. **审查、修订与结束。** 审查者检查建议是否符合需求、证据是否支撑结论；主管判断意见并安排修订。满足交付条件时提交，预算或返工上限耗尽仍有缺口时明确说明，避免无限循环。

这里的调查失败、证据冲突和审查意见，分别可能触发重试、补查或修订；它们要回到对应任务，并受预算与结束条件约束。这个例子用于解释流程，不代表已经验证了多 Agent 相对单 Agent 的收益。
