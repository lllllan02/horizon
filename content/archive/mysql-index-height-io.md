**树高不等于读盘次数：缓存命中可以减少读盘，范围扫描与回表又可能增加页面访问。** 树高只描述从根到叶子的层数，不能直接代表整条查询的 I/O 成本。

[[mysql-manual-queries#从 SQL 操作到 InnoDB|Buffer Pool 的缓存机制]]使 InnoDB 可以直接访问内存中的页，只有所需页不在缓存时才需要读入。例如一棵三层树，若路径上的根页、内部页已经缓存，只有目标叶子页缺失，就不需要为了这条路径读取三个磁盘页。这是简化示意，未计入预读、并发及其他访问。

反过来，一次查询也可能访问多于树高数量的页。范围扫描定位起点后还会继续读叶子页；二级索引查询需要其他列时，可能再访问聚簇索引。查找路径只是整个查询的一部分。

因此，树较矮意味着单次定位经过的层数较少，却不能直接推出整条查询的读盘次数或耗时。分析成本时应分开看「访问多少页」「哪些页已缓存」和「实际产生多少存储 I/O」。
