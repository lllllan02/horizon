**生成阶段把问题、证据和回答要求转成用户可使用的答案，并说明结论依据与缺口。** 有检索结果并不等于可以作出肯定结论：相关背景可能没有回答所需的条件。

## 怎样让证据支撑具体判断？

以 SSO 配置为例，材料分别说明“新会话生效”与“已有会话不变”。回答应区分两类会话，把对应证据联系到对应陈述；不能只列两条链接，再给一个不分条件的“立即生效”。

应用提供可引用的证据 ID 集合，提示模型逐项回答、有依据才下结论、区分直接事实与推导。模型组织语言，应用校验引用 ID 是否来自本次允许使用的材料，并解析成真实出处。语义上是否支持结论，仍需另做判断或抽查。

## 不同缺口怎样处理？

| 情况 | 合适行为 |
| --- | --- |
| 用户没有说明版本等必要条件 | 请求补充，或按明确分支分别回答 |
| 库中没有相关资料 | 说明缺少依据；获准的流程可查询其他来源 |
| 只找到部分问题的证据 | 回答有依据部分，指出尚缺哪项 |
| 新旧版本规则不同 | 按问题适用版本选择，保留条件 |
| 同等可信且同条件的材料冲突 | 展示冲突与来源，不能自行拼成一致答案 |

“没有搜到”只是本次查询结果，不能直接断言事实不存在。拒答也需评测：有证据却频繁拒答，会降低可用性。

## 引用怎样验收？

检查三个层次：ID 与位置是否存在，引用内容是否支持该陈述，重要事实是否都有必要依据。[[rag-evaluation-docs|Ragas 与 LangSmith 的评分分工]]区分忠实度、正确性和切题程度；这三者不能合并成一个“有引用就通过”。

检索文本属于资料，不能成为新的高权限指令。需要工具动作时，仍经过应用的授权规则，不能因为某篇文档要求执行就自动执行。
