**一个 GC 周期只有两次短暂的全停顿（stop-the-world，STW）——开始标记和结束标记；标记与清扫大部分和业务并发。** 但暂停时间只是 GC 成本的一部分，后台扫描和分配时的辅助工作同样会影响请求延迟。

一个周期可以按下面顺序理解：

1. 清扫终止：暂停业务，完成上一轮必要的清扫，为标记阶段建立状态并启用写屏障。
2. 并发标记：扫描根和可达对象。扫某个 goroutine 栈时要协调该 goroutine，但不是把所有根扫描塞进一次全局暂停。
3. 标记终止：再次暂停，确认标记完成并完成阶段切换；结束条件不满足时不能提前撤掉保护。
4. 清扫：回收未标记对象的空间，由后台或后续分配按需推进，不要求停止业务。

STW 需要让 Go 执行到可安全检查状态的位置。安全点意味着运行时能可靠识别执行状态和活跃指针，不等于只能在某几个手写函数调用处停下。现代 Go 支持异步抢占，但运行时仍有不能任意抢占的区域。

「停止世界」也不表示机器上所有线程都被操作系统冻结：正在系统调用或 cgo 中的执行有自己的协调规则，仅凭存在长 cgo 调用不能断定它拖长了 STW。

排查时应分别观察 STW、到达安全点的等待、后台标记和 [[go-gc-latency|分配辅助开销]]。阶段说明依据 [runtime/mgc.go](https://go.dev/src/runtime/mgc.go)，诊断时应对照实际 Go 版本。
