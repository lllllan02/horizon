**RAG 评测先判断任务是否完成，再沿实际数据流定位失败阶段。** 检索分数高、回答流畅、有引用，都不能单独证明系统可用。

## 先建立能解释结果的样本

每个样本保存问题、授权身份、资料快照、必要事实、支持证据和预期行为。覆盖精确名词、改写表达、条件与例外、多跳、无答案、版本冲突以及越权问题；调参集与最终检查集分开，避免只优化已见问题。

例如问题“修改 SSO 配置后现有用户是否要重新登录”，必要事实至少包含新会话行为和旧会话行为。两份重复文档都说明同一事实时，少取一份不一定意味着信息缺失。因此片段召回与事实覆盖必须分开。

## 检索与重排

[[recall-at-k|Recall@K]]检查标注相关项找回多少，[[precision-at-k|Precision@K]]检查前 K 项有多杂；[[mean-reciprocal-rank|MRR]]关注第一项相关证据出现多早，[[ndcg|NDCG@K]]关注分级相关性的排序。

比较召回时固定语料、切分、标注与 K；比较重排时固定候选与保留量。跨切分方案时片段定义变了，应补充稳定的必要事实覆盖。没有相关材料的样本单独评估，不能把零分母硬记为正常 Recall。

## 上下文与回答

对候选、入选材料、实际注入内容分别计算必要事实覆盖，定位压缩、拼接与截断造成的新增损失。条件、否定、例外及出处被改变时，即使 token 更少也不算优化。

答案检查分别使用不同参照物：正确性对可信事实，忠实度对实际证据，切题程度对用户问题，引用支持度对被引用原文。还要检查必要事实有没有表达、证据不足是否编造、有依据是否过度拒答。[[rag-evaluation-docs|官方评测资料]]解释了这些指标及自动裁判的局限。

## 怎样找到该改哪一段？

| 观察 | 优先核对与处理 |
| --- | --- |
| 原文有答案，规范化资料没有 | 解析、OCR、表格与过滤；修复后重新入库 |
| 资料有答案，候选没有 | 查询、切分、embedding、过滤与索引；比较精确基准 |
| 候选有答案，入选没有 | 融合、重排和保留预算；固定候选做对照 |
| 入选有答案，注入后丢失或失真 | 拼接、扩展、压缩与 token 计量 |
| 实际上下文足够，答案仍错 | 提示、条件应用、模型与引用校验 |

这些是诊断路径，不等于单一原因已被证明。可以给模型人工选出的充分证据做对照，以判断生成上限；这类“理想证据实验”不能计为端到端效果。

每次实验保存模型、提示、数据和索引版本，结合延迟分布、token、费用与权限失败看收益。自动裁判固定配置并用人工样本校准；未做实际实验时只记录方案和预期，不填写改善数字。
