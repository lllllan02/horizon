**「Mem0 的 2025 年论文将记忆形成分为事实提取和更新决策，并比较文本条目与关系图的效果。」** 本篇依据 v1 第 2—4 节；论文算法与 [[mem0-memory|当前 Mem0 API 和固定提交实现]]分别阅读，未复现实验。

## 为什么提取后还要比较旧记忆？

直接保存每轮摘要会重复记录，也可能保留相互冲突的事实。论文用新消息对、近期消息和异步维护的会话摘要提取候选，再为每个候选搜索相近旧记忆。

**「模型通过工具调用选择 ADD、UPDATE、DELETE 或 NOOP，程序执行结果」**。这样把「原话包含什么」与「知识库应改什么」分开；找到的旧候选是否完整、模型是否正确识别冲突，仍决定最终质量。

Mem0g 进一步抽取实体和关系，以有向图保存联系，服务需要组合关系的问题。图方案增加抽取、查询和维护成本，不能仅凭表示更丰富推断更适合。

## 实验支持什么取舍？

论文用 LoCoMo 比较问答质量、响应延迟和 Token 开销，在其设置下，提取后的记忆减少了完整历史输入的开销，图扩展在时间类问题上获益，但多跳问题未优于基础 Mem0。这些是特定模型、数据和评分协议下的结果，不能当作跨产品的固定性能排名；还需区分回答阶段成本与持续写入成本。

## 为什么接入前还要核对版本？

论文的**「四类自动操作属于研究算法」**。2026-10-13 核对的官方 Add 文档明确采用追加存储，不覆盖或删除已有记录。因此不能据论文推断今天一次 `add` 会自动纠正旧偏好；接入时仍应按目标版本验证 `add`、显式 `update` 及删除行为。
