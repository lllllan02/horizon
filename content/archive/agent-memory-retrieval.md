**记忆检索是按当前任务找回适用记录，并筛选出可放入模型上下文的内容的过程。** 外部记录再多，只有本轮真正读到的部分才会参与判断。

## 什么时候读取

少量必要约束可以常驻，详细经历和资料按需补查。这种[[memgpt-memory|分层记忆]]按「本轮是否需要看到」组织信息，与短期／长期的作用范围不同：长期偏好可以常驻，当前任务的大日志也可以外置。

读取可由程序在任务开始时触发，也可由模型在发现缺口后调用工具；[[letta-memory|常驻块与归档工具]]提供了后一种组织方式。每轮无差别重查增加成本，只在开始时查又可能漏掉中途出现的新问题。

![[assets/agent-memory-filter.png|当前任务只取回同一项目的有效记录，其他项目和旧版本不进入上下文]]

## 怎样找回适用记录

先由程序限定用户、项目和权限，再选择查询方式：已知属性，如示例语言，直接按字段查；类似排障经历可用关键词或语义召回，再比较环境、时间与结果。不能先把其他用户的信息交给模型再筛。

[[longmemeval-memory|检索粒度实验]]区分索引用的描述与返回的原文：可以用事实或摘要帮助定位，再返回带条件的证据片段。相似度高不代表适用，也不代表仍然有效。

## 怎样进入上下文

命中后回查当前版本，排除过期、删除与范围不符的记录，去重后按[[context-budget|输入预算]]选取。记录数量少也可能很长，需要按实际文本控制读取量。当前请求明确「这次用 Rust」时，历史默认语言不能覆盖它。

将内容连同来源和适用条件交给[[agent-context|上下文管理]]，作为背景使用。第三方文本与模型推断应保留各自身份，不能统一拼成高权限指令。

在[[agent-trace|执行轨迹]]中区分「召回候选」与「实际注入项」，再检查回答：正确记录没找到、被过滤，或读到后用错，需要修复的环节不同。评测使用隔离的记忆快照，并加入相似但属于其他项目的记录；只增加召回数量通常解决不了范围错误。
