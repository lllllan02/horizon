**一致性哈希把节点和 key 映射到同一个哈希环，通常让 key 归属顺时针遇到的第一个节点。** 增删节点只改变相邻区间的归属，避免了 `hash(key) % 节点数` 那种大范围重映射。

- 理想均匀条件下，从 N 个节点加一个，新节点平均承接约 `1/(N+1)` 的 key；移除一个平均影响约 `1/N`。这是分布的**期望**，不是每次扩容的实测迁移比例，也不保证每个节点负载相等。
- **虚拟节点**让一台机器在环上占多个位置，通常能改善分布，还可按容量分配不同数量的位置；但一个特别热的 key 仍会落到它负责的节点上，虚拟节点拆不开这个热点。
- 改变路由**不会自动搬数据**：客户端和服务端要有一致的成员视图、故障判定与迁移安排；迁移期间的读写、旧值回填和重复请求都要额外处理。
- **固定槽位**是另一种间接映射：先把 key 映射到槽，再维护槽到节点的关系。Redis Cluster 用固定 16384 个槽与 CRC16，不是把节点放到哈希环上。两种方式都部分解耦「数据归哪组」和「哪台机器负责」，但算法不同。

用于数据库时还要结合 [[database-sharding|查询路由与迁移成本]]；用于缓存时，要为迁移造成的集中未命中预留后端容量。
