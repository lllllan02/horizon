**记忆存储是把事实、偏好和经历组织成可定位、可更新、可追溯记录的方式。** 它解决「信息留下后，以什么单位保存、以后怎样找到和纠正」的问题。

## 记录要保留什么

只保存「喜欢 Go」容易丢失条件：它可能只适用于某个项目的示例。记录至少要能说明内容、适用范围与来源；需要纠正和并发更新时，再加版本与有效状态。

![[assets/agent-memory-record.png|一条记忆的内容、适用范围与来源共同组成可维护的记录]]

实际服务还应从可信会话绑定用户身份。来源用于回查依据，版本用于识别旧状态；字段齐全并不能保证提取的内容正确。

## 选用文件还是数据库

少量项目规则与经验可用 Markdown／JSON，加一个简短索引定位主题；[[claude-code-memory|索引与主题文件]]便于人工审阅。属性固定、需要多人并发和条件更新时，可用数据库按用户、项目与属性定位，避免每次重写整份档案。

大量经历可保存为独立条目，再增加关键词或向量索引。索引负责发现候选，正文与来源仍需保留；[[graphiti-memory|时序关系图]]适用于还要查询实体关系与历史变化的场景，也增加抽取和维护成本。无需为「长期记忆」预先引入所有组件。

## 从可检查的实现开始

[[assets/agent-memory-demo.go|Go 文件示例]]演示偏好写入、读取、纠正、到期和删除。可用 `go run content/assets/agent-memory-demo.go -h` 查看参数；它接收已确认的值，不自动从对话提取，且只适合单写入者顺序演示，版本检查不能阻止并发覆盖。

接入[[anthropic-memory-tool|文件记忆工具]]时，程序仍要限制路径与读写范围。若正文和检索索引分开保存，命中后回查当前正文与版本，避免旧索引重新带回已纠正的值；索引刷新失败需要重试。验证时用新进程读取，并测试换用户、换项目与旧版本写入。
