## 项目与整体编排

我独立负责了一个题库项目的整个后端，并从 0 到 1 落地了其中的学习计划 Agent。用户用自然语言描述学习需求，助手结合用户的学习情况，从题库中选出具体题目，形成学习清单。

整体采用「**外层 Workflow 编排，其中一个节点运行 ReAct Agent**」的结构。Agent 节点负责澄清需求、分析用户画像和检索选题；后续 Workflow 节点负责结果校验，校验通过就返回，不满足要求就进入降级分支。

## Agent 节点：理解需求与个性化选题

我考虑过把选题过程中的每一步都拆成固定 Workflow，但觉得拆得过细，所以在系统提示词里定义了一套「**软约束的 Plan 模板**」，给 Agent 建议性的执行路线：

1. **澄清需求**：拆解用户需求，对不明确且影响选题的条件，通过与用户交流进一步确认。
2. **分析用户画像**：调用学习情况查询工具，了解当前课程内容、近期做过的题目类型，以及具体提交记录和通过情况，分析学习阶段与薄弱项。
3. **生成选题草稿**：先明确需要什么范围、类型和难度的题目，此时还没有具体题目来源。
4. **检索并提交清单**：调用题库工具，按标签、知识点、难度等条件查询数据库，组合成具体清单，再[[learning-plan-agent-submission|调用提交工具保存清单]]。

提交工具保存清单后，模型再生成一轮文字建议，随后 ReAct Agent 节点结束，由外层 Workflow 继续处理。

## 后续 Workflow 节点：校验与降级

Agent 提交结果后，程序先检查题目是否存在、数量是否满足要求，再由模型判断题目是否符合用户需求。通过后返回；未通过则进入[[learning-plan-agent-fallback|只按用户需求检索并直接返回的降级流程]]，不再校验或重新生成。

## 上线情况

这个功能已经上线给真实用户使用。题库本身的用户基数较小，具体使用量和效果数据还需要核对，目前不报告未经确认的规模、推荐质量或耗时提升数字。
