父子 Agent 通常采用[[multi-agent|委派模式]]：父 Agent 通过工具调用或其他接口，把子任务、必要输入和输出要求交给子 Agent。任务边界清楚时，子 Agent 独立执行，最后返回结果即可，不需要频繁的中间交互。

需要父 Agent 的历史信息时，**可以传完整历史，也可以先筛选或摘要，只传相关内容**；全量传递要考虑上下文窗口和信息隔离要求。历史存在文件里，可以复制或读取指定文件；存在数据库里，可以通过父会话 ID 查询指定范围的历史。无论怎么存，最后都要由程序把需要的信息组装进子 Agent 的[[agent-context-input|模型输入]]，模型才能看到。

如果执行中还需要补充信息、汇报进度或发送取消信号，同一进程内可以通过内存队列或 Channel 交互，跨进程、跨服务则可以使用 RPC 或消息队列。收到的消息由程序处理，需要模型理解的内容再加入后续上下文。
