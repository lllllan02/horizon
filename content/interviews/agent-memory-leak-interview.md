Agent 服务常有两个特点：**多轮调用模型，需要组装较长的历史[[agent-context|上下文]]；模型生成和流式输出耗时较长，请求与连接持续较久。** 因此我会重点检查三类问题：

- **历史数据累积**：消息和工具结果一直留在内存中，需要限制保留量、清理过期会话。无用数据仍被引用属于[[memory-leak|内存泄漏]]；仍在使用的数据过多则是容量问题。
- **协程和流未正确清理**：用户断连时停止向该连接推流、清理推送资源，后台任务继续执行。任务结束、[[agent-cancellation-interview|显式取消]]或任务超时后，应确保相关协程退出、上下文释放。
- **其他资源未释放**：文件句柄等资源也要在正常和异常路径中及时释放。

排查时结合内存、协程和连接数的趋势；Go 服务可用 heap、goroutine profile 定位。修复后验证断连时推送资源能释放、后台任务能继续，以及任务完成、取消、超时或失败后能正常清理。
