Agent 服务通常需要**多轮调用模型、保留历史消息和工具结果，模型调用等待较长，并且经常使用流式返回和异步任务**。这些特点容易带来以下几类内存问题：

- **历史数据持续累积**：多轮调用会积累历史消息、[[agent-context|上下文]]和工具结果。如果一直放在 map、数组或缓存里，没有上限和清理机制，内存就会不断增长。需要限制保留量并清理过期数据；不再需要的数据仍被引用，属于逻辑上的[[memory-leak|内存泄漏]]，仍然需要但数量太多，则是容量问题。
- **等待中的请求积压**：模型调用等待较长，下游变慢时，大量请求及其上下文可能同时留在内存中。需要用[[concurrency-control|并发上限]]和[[service-backpressure|背压]]控制积压，这类内存增长不一定是泄漏。
- **任务和资源未随请求结束而清理**：流式返回和异步任务中，用户断连或请求[[timeout-and-deadline|超时]]后，如果任务没有退出、响应流和连接没有关闭，就可能继续占用资源和内存。需要传递[[agent-cancellation-interview|取消信号]]，确认任务退出，并及时关闭资源。

**排查与验证**：我会结合内存、goroutine、连接数和队列长度的变化，用 heap 和 goroutine profile 定位。修复后重点验证断连、超时和失败场景，确认数据、任务和资源能正常清理。
