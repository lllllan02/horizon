我会从开发的角度来回答：先明确 Agent 要完成什么业务、怎样算完成，以及成本、响应时间和操作权限这些约束，再**「从一个最小的 Agent Loop 写起，围绕业务逐步补齐能力」**。

最小的 [[agent-loop|Agent Loop]] 要能组装上下文、调用模型和执行工具。模型返回工具调用请求后，由程序执行工具，再把结果交回模型，让它继续判断下一步，直到返回最终回答，或者达到步数、时间等限制。工具按照业务场景提供，把用途、参数和返回结果说明白，让模型能够选择合适的工具完成任务。

随着对话和任务变长，历史消息和工具结果会越来越多，就需要补充[[agent-context|上下文管理]]，比如用滑动窗口保留近期消息，或者把较早的内容压缩成摘要。处理时要保留用户要求、任务进展和关键结果，让模型能够接着完成任务。

基础业务跑通之后，再根据实际问题完善 [[agent-harness|Harness，也就是围绕模型运行的程序和配置]]，比如增加超时重试、状态保存和中断恢复。实现时可以按需要使用 LangChain 等框架，具体取决于我们需要哪些能力。

同时，**「基础观测和评测从最小版本就开始做」**。通过[[agent-trace|埋点记录模型和工具的调用过程]]，结合[[agent-evaluation|评测]]观察任务成功率、耗时和成本。后续根据失败案例判断问题出在哪里，再修改提示词、工具或上下文策略，逐步补充能力，并验证改动有没有改善效果。
