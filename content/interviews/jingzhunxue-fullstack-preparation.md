这份岗位围绕「**将教育大模型能力做成可复用、可维护、可规模复制的教学系统**」展开：既要实现诊断、讲解、追问和个性化引导，也要支撑实时交互、低延迟推理与大规模教育数据。虽然附件标题为全栈开发工程师，正文主要描述 Agent 与后端工程，前端职责需要另行确认。

依据为 2026-10-21 完整读取并保存的 Word 附件，Markdown 原文及对应 Word 副本位于 `content/sources/全栈开发工程师-浙江精准学教育有限公司.md` 和同名 `.docx`。以下优先级、检验问题、评测与完成证据是准备建议，不是公司真实考纲；未评估个人掌握程度，也未执行练习或性能测试。

## 要求性质与准备顺序

| 原文性质 | 要求与边界 |
| --- | --- |
| 附件中的岗位条件 | 杭州西湖区，年包 40W–80W（可沟通）；公司介绍写早十晚七、弹性不打卡、周末双休。均为附件陈述，当前条件及薪酬构成待确认 |
| 工程挑战 | 高并发、低延迟、强一致性；单机万级长连接、毫秒级推送、消息零丢失；推理、上下文和检索优化；图文／语音可控稳定；千万级教育数据的索引、缓存、实时更新与回溯 |
| 明确工作职责 | 教育 Agent；与 ML Engineer 协作推理优化及后训练工程支撑；并发、消息、缓存与高可用、可观测、可扩展的后端架构；AI 辅助方案设计、编码重构和复杂问题定位 |
| 原文未给出的门槛 | 未单列学历、年限、语言、框架、前端技术栈、必备履历或加分项，不能照搬其他岗位要求 |

P0 先串起教学任务、实时可靠性和性能优化，便于解释产品怎样工作、哪里会失败；P1 再补齐数据、多模态、ML 协作和日常交付。**P1 同样对应核心职责**，只表示准备顺序。“万级”“毫秒级”“零丢失”列在挑战部分，没有负载、硬件或故障边界，不能据此认定公司已经达到，也不能直接作为个人履历要求。

## P0：教育 Agent 怎样完成教学任务？

对应：诊断、讲解、追问、个性化引导；产品介绍中的持续诊断与动态干预。

- [ ] **串起一轮教学过程**：学生答错一道题后，系统根据哪些答题记录判断薄弱点，何时追问、怎样选择讲解或下一题，何时停止？说明模型、业务程序、题库工具和学习状态各自负责什么。
- [ ] **检查教学结果与失败处理**：知识点判断错误、题目缺失、模型给出错误讲解时，怎样发现、纠正或降级？参考[[agent-evaluation-interview|Agent 效果评测]]，为诊断、讲解与个性化分别提出可检查的结果，不只展示对话是否流畅。

完成证据：一条包含输入、工具、状态变化、输出和失败分支的教学链路，以及代表性样例与判断标准。已有[[learning-plan-agent-interview|学习计划 Agent 项目]]可用于解释画像、检索选题、校验和降级；诊断、授课及实际学习效果仍需另补证据，不能由选题功能直接推定。

## P0：长连接与消息怎样在故障后保持可靠？

对应：单机万级长连接、毫秒级推送、消息零丢失；并发控制、消息系统、强一致性及高可用架构。

- [ ] **定义并验证连接容量**：连接协议、单机配置、连接数、每秒消息量、消息大小与活跃比例分别是什么？怎样处理心跳、重连风暴、慢客户端、并发访问和背压？区分保持连接的能力与实际推送吞吐。
- [ ] **追踪一条消息的交付过程**：消息在哪一步持久化、何时确认、断线后从哪里补读？针对写入后宕机、发送后未确认、重复投递与乱序，说明恢复方法及业务结果。可从[[agent-stream-recovery-interview|Agent 断线恢复]]出发，但需明确具体方案的持久化与保留边界。
- [ ] **划定一致性与可用性边界**：哪些状态必须强一致，哪些数据允许延迟更新？多连接、多实例同时修改学习进度时怎样处理冲突？实例故障、滚动发布与流量增长时，怎样迁移连接、恢复状态并扩大容量？

完成证据：连接与消息时序、确认和重放规则、并发与故障用例；报告实际负载下的延迟分位数、错误、丢失、重复及资源消耗。“零丢失”必须附消息类型、确认语义、保留时间和故障范围；未实测时只提交设计与验证计划。

## P0：怎样定位并优化教学链路的延迟？

对应：推理性能、上下文管理、检索效率与低延迟工程化。

- [ ] **按阶段定位瓶颈**：从学生输入到首个反馈、再到完整回答，分别统计接入排队、检索、上下文组装、模型推理和推送耗时。沿[[api-latency-interview|性能排查主线]]提出优化假设，说明怎样验证，而非直接换模型或增加缓存。
- [ ] **控制上下文成本与信息损失**：哪些历史、学生状态和检索结果必须保留，哪些可摘要或按需读取？结合[[history-storage|对话历史存储]]，说明压缩、截断或模型切换后，怎样检查关键事实、工具结果及个性化约束仍然有效。
- [ ] **同时检查检索速度与有效性**：按知识点、难度或学生条件查询时，怎样选择索引、过滤和排序？如何区分没检索到、检索到错误材料和模型没正确使用？采用 RAG 时可参考[[rag-workflow-interview|检索与生成流程]]，原文未指定必须使用向量库。

完成证据：同一任务集、数据版本和负载下的优化前后对比，包含首个反馈、完整响应、尾延迟、成本及教学质量。说明优化改变了什么，以及质量和资源上的代价；不预设公司采用某个推理框架。

## P1：千万级教育数据怎样更新并回溯？

对应：教育数据的索引、缓存、实时更新与回溯，以及后端缓存体系。

- [ ] **从访问模式设计数据链路**：题目、知识点、学习记录等数据怎样组织、建立索引与缓存？更新或删除后，数据库、索引和缓存怎样同步，积压或部分失败怎样恢复？结合[[cache-consistency-interview|缓存一致性]]，解释时效、查询成本和一致性要求之间的取舍。
- [ ] **还原一次历史教学决策**：怎样找到当时使用的题目、学生状态、检索结果、提示词和模型版本？先确认“回溯”指历史版本查询、决策解释还是数据回滚，再设计记录与恢复范围。

完成证据：数据模型、读写与更新流程、版本规则，以及更新失败、删除后旧索引命中和历史记录查询的用例。性能数据须注明实际数据规模；“千万级”具体指记录、题目、文档还是索引条目仍待确认。

## P1：图文和语音怎样稳定参与学习？

对应：多模态（图文／语音）在真实学习流程中的可控与稳定性。

- [ ] **处理输入不确定性**：拍题模糊、公式识别有歧义、语音识别错误或输入不完整时，怎样发现并让学生确认？说明输入怎样关联到同一道题和当前教学轮次，避免直接沿错误内容继续讲解。
- [ ] **控制输出与异常恢复**：图片解析、语音识别或语音输出超时、失败时怎样反馈与降级？若支持流式语音和打断，怎样同步文字、音频、任务状态并处理迟到输出？具体交互能力需向团队确认。

完成证据：一条图文或语音学习流程，包含识别歧义、超时、重试、取消与恢复样例。可先选择一条链路练习，并说明另一模态尚未覆盖；不推断岗位要求开发硬件或训练多模态模型。

## P1：怎样与 ML Engineer 协作后训练与推理优化？

对应：推理链路设计与优化；后训练中的 RL、风格对齐、个性化适配的工程支撑。

- [ ] **说明推理协作接口**：应用侧提供哪些调用约束、任务样例和链路指标，ML 侧负责什么？模型升级后，怎样检查教学行为、接口、上下文与延迟变化，发现退化时怎样回退？
- [ ] **提供可追踪的后训练反馈**：哪些教学轨迹、错例与反馈适合交给 ML 团队，怎样说明数据来源、版本、使用权限和质量？区分应用日志、训练样本、奖励或评价信号，说明各自由谁定义和验收。

完成证据：应用与 ML 的职责边界、数据或接口约定、一次模型变更的评估与发布方案。原文要求工程支撑，没有写独立负责 RL 算法研究或从零训练；具体训练参与深度待确认。

## P1：怎样用 AI 改善日常工程交付？

对应：AI 辅助方案设计、编码与重构、复杂问题定位；系统可复用、可维护，并具备可观测性。

- [ ] **展示一次有依据的 AI 辅助改动**：AI 在方案比较、实现或重构中提供了什么，自己怎样核对约束、评审差异、验证行为？说明发现过哪些错误建议，以及最终保留或放弃某个方案的理由。
- [ ] **复盘一次复杂问题定位**：从症状、日志、指标或追踪记录提出假设，说明 AI 怎样帮助缩小范围、如何用证据排除误判，以及修复后怎样验证。将模型、检索、消息与业务步骤关联起来，解释如何定位某次教学失败。
- [ ] **说明系统怎样持续维护**：哪些能力适合抽为复用模块，接口、测试与版本怎样管理？说明扩展新课程、教学策略或模型时需要改动哪些部分，以及怎样评估质量、可用性和性能。

完成证据：真实改动差异、关键判断、验证结果及个人贡献；补做练习时明确标注练习。只展示生成代码或工具名称不足以说明工程效率与质量已经改善。

## 面谈前需要确认什么？

- **岗位边界与技术栈**：前端、服务端、Agent、推理服务和数据平台各占多大比重？使用哪些语言、框架、协议与存储？学历、年限和必须经历是否另有完整要求？
- **性能与可靠性口径**：万级连接、毫秒级推送和千万级数据的硬件、负载、统计口径是什么？哪些是现状、哪些是目标？强一致性覆盖什么状态，“消息零丢失”覆盖什么故障？
- **教学与 ML 分工**：教学质量由谁定义与验收，现有诊断和个性化系统做到哪一步？多模态、后训练与回溯分别由本岗位承担到什么深度？
- **岗位条件**：薪酬固定、奖金及其他部分怎样组成，实际办公地点和工作安排是什么，职位是否仍在招聘？融资、销量、数据量和产品唯一性等介绍未作为本清单的已核实事实。
