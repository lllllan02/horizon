[[tool-calling|工具调用]]中，程序先定义工具名称、用途和参数结构，模型选择工具并生成本次调用的参数值。程序负责校验、找到对应实现并执行，再按调用 ID 把结果交回模型，让它继续判断下一步。

流式接收时，要等这次调用的参数生成完整，再校验执行。使用框架可以复用它的参数聚合和完成判定，但仍要处理断流、截断和取消，不能执行残缺调用。

拿到完整参数后，我会逐层校验：先检查 JSON 能否解析，再检查字段、必填项和参数类型是否符合 Schema，然后检查值是否符合业务规则，以及资源是否存在、当前用户是否有权操作。[[tool-permissions|权限判断]]使用服务端掌握的真实身份和授权信息，不能直接相信模型传入的用户 ID 或租户 ID。[严格结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)可以约束输出符合 Schema，业务含义和权限仍需程序检查。

失败之后，要按原因分别处理：

- **参数错误**：不执行工具，把具体字段和错误原因反馈给模型，让它在次数和时间预算内修正。
- **权限不足**：拒绝执行；需要申请授权时进入相应流程，不能靠模型修改参数绕过。
- **模型拒绝**：识别拒绝状态，向用户说明或结束当前路径，不能当作格式错误反复要求重生成。
- **工具失败**：明确的业务失败反馈给模型，用于解释或调整后续操作；临时故障由程序判断是否可以安全重试。

尤其要注意，**「工具超时不代表操作没有成功」**。创建订单、扣款等操作没收到结果时，应先查询业务状态，或依靠业务幂等机制防止重复执行。调用 ID 只负责关联请求和结果，本身不能保证重试安全。
