在[[learning-plan-agent-interview|学习计划 Agent 项目]]中，我们选择在选题验收失败后直接降级。**初步上线时优先控制延迟和 Token 消耗，接受较低标准的结果，再通过失败样本推进后续优化。**

## 失败现象与校验

实际遇到过两类问题：

- **编造题目**：模型没有检索，或者对检索结果不满意后，生成题库里不存在的题目。
- **选题偏离需求**：查到了真实题目，但搜索方向偏离了用户需求，最终清单不合适。

原因可能包括工具设计不够合理，也可能是用户需求与当前题库覆盖的内容不匹配。这些是需要结合具体请求验证的假设。

针对这些问题，后续 Workflow 节点会依次校验：

1. **程序校验**：检查题目是否存在、数量是否满足要求。
2. **模型判断**：检查题目是否符合用户需求，通过后才返回。

## 初期上线：用降级控制延迟与成本

如果结果不满足要求，就进入「**只按用户需求检索的降级流程**」：拆解用户明确提出的需求，检索一批题目，省去用户画像分析。**降级结果直接返回，不再进入新一轮校验或重新生成。**

作为初步上线的功能，我们希望控制延迟和 Token 消耗，因此选择按较低标准完成这次交付，避免反复校验和生成；代价是放弃主流程的个性化适配和完整验收要求。

## 降级记录与后续优化

我们会对降级动作记录日志并给出相应提示，通过这些信息定位具体请求，尝试将典型失败请求加入评测集。后续准备另一版方案时，再围绕这些样本研究工具设计、题库覆盖和选题流程的改进。
