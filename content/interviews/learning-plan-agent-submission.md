在[[learning-plan-agent-interview|学习计划 Agent 项目]]中，我选择「**通过工具提交并保存题目清单，再让模型回复文字建议**」，分别承载程序要读取的业务数据和面向用户的自然语言内容。

## 原来的问题：最终回复混入文字

程序需要拿到一份可解析的题目清单，所以最初希望模型在最后返回 JSON，哪怕只是一个题目 ID 数组也可以。但实际会出现 JSON 前后夹带自然语言的情况，不能直接把整段回复作为 JSON 解析。

同时，执行过程中需要流式输出文字，向用户说明进度；最后也希望模型补充一些学习建议和解释。因此，我们需要同时交付结构化清单与自然语言内容。

## 最终方案：工具提交，文字收尾

我们考虑过用模型支持的强制结构化输出能力约束最终回答，最后选择为清单设置独立的提交工具，把数据提交和文字回复分开：

1. **提交清单**：模型判断清单已生成时，[[tool-calling-interview|调用提交工具]]，将清单等业务参数作为工具入参传给程序。
2. **保存答案**：程序执行工具，接收这些参数并保存清单。
3. **生成文字回复**：保存成功后，再调用一轮模型，返回建议、解释等自然语言内容。随后 Agent 节点结束，进入外层 Workflow 校验。

## 取舍：分开交付数据与文字

这个方案让清单有了明确的提交和保存入口，同时保留过程叙述与最终建议；代价是需要维护提交工具和结果保存逻辑。

**工具提交明确了结果交付方式，题目本身是否正确仍由后续验收判断。** 题目存在性、数量和需求匹配检查，以及失败后的[[learning-plan-agent-fallback|直接降级取舍]]，由外层 Workflow 处理。
