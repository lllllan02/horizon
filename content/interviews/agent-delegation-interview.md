我会先看任务「**能不能拆**」，再看「**值不值得拆**」，判断是否交给[[multi-agent-benefits|多个 Agent]]。

能不能拆，主要看任务边界是否清楚，每个子任务是否有明确的输入、产物和验收标准。有前后依赖也可以拆，只要交接关系明确，下游等前置结果具备后再执行。

值不值得拆，我会从三个方面判断：

- **执行和信息组织**：相对独立的工作可以并行推进，缩短等待；资料较多的任务可以分开处理上下文，只返回关键成果与依据，减少无关信息干扰。
- **分工与检查**：按子任务选择合适的工具或模型，也可以让另一位 Agent 独立查证、审查成果，尝试发现原过程的遗漏。
- **复用与维护**：把专业能力封装成可调用的 Agent，供不同流程组合，并分别开发和维护。

最终要以单 Agent 为基准，比较收益与启动、沟通、汇总和核查成本。单 Agent 配合并行工具、Skills 或工作流也能满足部分需求；**收益超过新增成本才值得拆**，需要频繁同步大量信息的任务通常更适合留在同一个 Agent 中。
