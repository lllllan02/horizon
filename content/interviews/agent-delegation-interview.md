我会从「能不能拆」和「值不值得拆」两层判断任务是否值得[[multi-agent#哪些工作值得独立委派？|交给多个 Agent]]。

## 能不能拆

先看任务或模块之间的边界是否清楚，输入、产物明确后，能否独立完成和检查。有前后依赖也可以拆，只是下游要等前置产物具备后再执行。能拆，还要进一步判断有没有必要拆。

## 值不值得拆

我会以单个 Agent 完成为基准，比较拆分后的收益与新增成本。收益主要有两类：

- **减少上下文干扰**：长任务可能触及上下文窗口，需要反复压缩。拆开后，把检索、试错等过程留在各自上下文，只将必要产物、依据和约束作为下一任务的输入，减少后续需要携带的信息。
- **缩短整体耗时**：相互独立的分支可以并发推进，减少串行等待；存在前置依赖的部分仍按顺序执行。

拆分也会增加「**协作与沟通成本**」：启动各个 Agent、交代上下文、协调进度，再汇总和核对结果；分工重叠或理解不一致时，还可能需要纠正和返工。这些过程会增加模型调用与 Token 消耗，协调和等待也可能抵消并行节省的时间。

**只有收益超过这些新增成本，才值得拆。** 任务很短、需要共享大量上下文或频繁来回确认时，通常留在同一个 Agent 中更合适。
