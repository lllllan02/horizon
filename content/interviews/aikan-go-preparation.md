这份岗位要求「**独立承担 Go 服务端架构、业务开发与线上调优，同时具备前端页面开发和 AI 编程工具使用能力**」。准备重点是用真实项目证明设计、实现和维护能力，再围绕 Go、网络与存储解释定位问题和验证改动的过程。

依据为 2026-10-20 导入的[爱看互动 Go/Golang 高级开发工程师 JD](https://www.zhipin.com/job_detail/58844ce16da40d750nJ53t20E1dQ.html)，本地原件为 `content/sources/「GoGolang 高级开发工程师(base杭州)招聘」_爱看互动招聘-BOSS直聘.md`。已核对全部职责、任职要求与硬性要求；下列问题、准备顺序与证据是准备建议，不是公司真实考纲。招聘状态及薪资未另行核实。

## 要求性质与准备顺序

| 原文性质 | 要求与边界 |
| --- | --- |
| 页面展示条件 | 杭州、30–50K、5–10 年、本科；具体薪酬口径与学历条件待招聘方确认 |
| 明确任职经历 | 五年以上后端开发经验，并具有 Golang 生产环境项目经验；不能改写成「五年 Go 经验」，也不能用短期练习替代履历 |
| 明确能力要求 | Go 并发、GC、内存管理与调优；TCP/IP、HTTP/2、WebSocket 与网络调优；分布式、缓存、消息队列、MySQL 与 NoSQL；架构判断、学习、解决问题、沟通协作；前端业务与 Web 页面开发 |
| 明示硬性要求 | 熟练使用 Cursor 等 AI 编程软件；原文没有限定只能使用 Cursor，也未要求每款工具都会用 |

先准备履历、架构主线、Go 与 AI 编程证据（P0），再覆盖网络、存储、前端和协作（P1）。顺序依据岗位的 Go 后端定位和明示硬性要求；「**P1 同样属于明确要求**」。原文没有明示优先或加分项，不额外设置 P2。

公司介绍提及 AIGC 与短剧，但职位正文未要求 Agent、RAG、模型训练或音视频编解码研发经历，也未指定前端框架、NoSQL 产品与消息队列产品。以下失败处理、验证与发布问题是为完成职责推导的准备点。当前未评估个人能力，勾选仅记录准备完成情况。

## P0：履历、业务理解与架构责任

对应：职责 1–3，任职 1、5。

- [ ] **核对真实履历**：本科、后端年限与 Go 生产项目经历分别是什么？能否说明上线时间、个人负责范围，以及生产系统与个人练习的区别？
- [ ] **讲清一个业务的完整实现**：需求解决什么问题，怎样形成接口、模块和数据设计？沿一次请求说明自己负责的代码、依赖、上线和后续维护。
- [ ] **复盘一次架构决策**：业务规模、交付时间、性能与维护成本怎样影响方案？比较候选方案，解释为何接受当前复杂度，以及什么变化会促使技术升级。

完成证据：一份项目介绍、架构与请求流程图、一项实际决策及结果。没有承担过「主导架构」时如实说明职责，不把参与经历扩大成独立负责。

## P0：Go 基础、并发与内存调优

对应：任职 2，以及职责中的线上代码调优。

- [ ] **解释核心代码与并发设计**：结合实际代码说明切片、map、接口、错误与资源生命周期；用[[go-gmp-interview|GMP 调度模型]]解释并发与并行，Channel、锁、取消与并发上限如何配合？怎样定位竞态、阻塞或 goroutine 无法退出？
- [ ] **讲清 GC 与内存管理**：说明栈与堆、对象存活、GC 的基本过程及其开销；结合[[go-escape-interview|逃逸分析与堆分配]]解释某个热点为什么值得优化，哪些结论依赖实际 Go 版本。
- [ ] **完成一次性能排查复盘**：CPU 升高、延迟变长或[[go-oom-interview|内存持续增长]]时，如何提出假设、采集性能数据、定位代码并复测？怎样区分分配过多、对象保留、任务积压和并发峰值？

完成证据：关键代码、并发失败用例、性能分析材料，以及同一环境和负载下的改动前后比较。保留 Go 版本、吞吐、延迟、错误率与资源数据；未做过的实验保持未完成。

## P0：AI 编程工具的实际使用

对应：明示硬性要求「熟练使用 cursor 等 AI 编程软件」。

- [ ] **演示一次完整研发任务**：使用实际熟悉的工具，从理解已有代码、提供上下文、拆分任务，到修改、运行和排错，说明哪些步骤由工具完成、哪些由自己判断。
- [ ] **解释如何检查生成代码**：展示发现错误、遗漏或过度修改的实例；如何审查业务语义、依赖、资源释放和测试结果，确保自己能解释并继续维护代码？

完成证据：一段可复现的操作过程、最终代码差异和验证结果。只展示提示词或生成截图不足以说明交付能力；是否指定 Cursor、是否现场演示及能否使用其他工具，面试前确认。

## P1：网络协议与网络性能

对应：任职 3。

- [ ] **解释请求与连接过程**：TCP/IP 各层怎样参与一次服务请求？连接建立与关闭、重传、连接复用、超时分别影响什么；HTTP/2 的流、多路复用与流量控制如何影响并发请求？
- [ ] **说明 WebSocket 的使用与维护**：结合[[websocket-sse-interview|实时通信的协议选择]]说明何时需要双向通信；连接建立后，心跳、断线重连、慢客户端与消息积压怎样处理？
- [ ] **准备一次网络调优证据**：请求变慢时，怎样区分解析、建连、网络传输、服务处理与客户端接收耗时？用哪些日志、抓包或指标验证瓶颈，怎样比较调优收益与资源代价？

完成证据：协议过程图、连接或请求记录，以及一次真实网络调优复盘。练习可补协议理解，但不能冒充原文要求的调优经验；公司使用哪些协议、是否有长连接业务仍待确认。

## P1：分布式、存储与系统性能

对应：任职 4，以及系统问题处理和业务维护职责。Redis、Kafka 可作为熟悉的例子，不视为原文指定产品。

- [ ] **解释分布式失败处理**：多实例并发、下游超时、重试与实例退出时，怎样判断业务结果、避免重复效果，并限制故障影响？哪些问题需要事务、幂等或一致性协调？
- [ ] **准备 MySQL 与 NoSQL 选型案例**：数据和访问模式是什么，为什么选择关系型或某一种 NoSQL？结合[[mysql-slow-query-interview|慢查询优化]]说明索引、事务、锁与连接等待怎样定位，比较修改前后的正确性与开销。
- [ ] **说明缓存与消息队列边界**：基于[[redis-interview-index|缓存与 Redis]]解释数据更新、失效、热点和故障；基于[[kafka-interview-index|消息队列]]解释异步处理、重复消费、顺序与积压。哪些数据必须可靠保存，怎样验证恢复结果？
- [ ] **串起一次线上问题处理**：从[[api-latency-interview|接口耗时排查]]出发，如何缩小范围、定位瓶颈、止血、修复与验证？怎样确认局部优化没有把压力转给其他组件？

完成证据：数据与依赖图、一项存储或异步设计、一次故障复盘和性能对照。说明业务规模、数据分布与测试条件，不预设公司吞吐或可用性门槛。

## P1：前端业务交付与协作

对应：任职 6、7，以及深入理解需求、业务开发和维护职责。

- [ ] **展示一个可用的业务页面**：用熟悉的技术完成列表、表单或详情等业务流程；说明页面状态、接口调用、加载与错误反馈、输入校验及前后端联调怎样处理。选实际项目或明确标注的练习，不预设必须使用 React 或 Vue。
- [ ] **复盘一次需求协作与问题解决**：怎样澄清含糊需求、沟通方案代价、处理线上反馈并推动修复？学习过什么新技术，为什么采用或放弃，怎样帮助团队维护？

完成证据：页面演示与代码、一次协作或学习记录，写清个人行动和实际结果。踏实、责任心与钻研精神通过具体经历表达，不用自我评价替代。

## 面试前待确认

- [ ] **确认工作范围**：现有 Go 版本、架构与业务规模，网络协议的实际场景，NoSQL 与消息队列产品，主导架构的责任边界，以及前端开发占比和技术栈。
- [ ] **确认招聘与考察条件**：学历及年限口径、薪资构成、AI 编程工具要求，以及是否包含编码、网络排障、系统设计或前端实操。

本清单覆盖原文职责 1–3、任职 1–7 和 AI 编程硬性要求；尚未核实公司面试流程、评估个人差距或执行清单中的练习。
