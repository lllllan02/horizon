这份岗位围绕「**让购物 Agent 完成搜索、比价、采购规划和下单任务，并对实际执行效果负责**」展开。重点是实际 Agent 项目经验、后端交付能力，以及复杂任务中的可靠性、效率和成本；准备应沿购物任务与业务系统的连接展开。

依据为 2026-10-20 保存的[AI Agent 工程师（电商）JD](https://www.zhipin.com/job_detail/bd23e764c4a2b7cc0nx40t-8FldY.html)，本地原件为 `content/sources/「AI Agent 工程师（电商）招聘」_四川斯茂瑞企业管...招聘-BOSS直聘.md`。已核对职位概述、全部核心职责、任职要求、优先经验和加分项；以下问题与完成证据是准备建议，不是公司真实面试题。

## 岗位与要求性质

剪藏中的招聘主体为四川斯茂瑞企业管理咨询有限公司，Saparo 是 JD 介绍的面向北美市场的 AI 消费助手产品名。页面概要标示杭州、25–45K、3–5 年、本科，工作地址为余杭区西溪八方城 9 幢；正文称岗位直接向 CEO 汇报。招聘主体、产品团队关系与当前招聘状态尚未另外核实。

| 原文性质 | 保留的要求与边界 |
| --- | --- |
| 必备学历与经历 | 相关专业本科及以上；实际 Agent 项目开发经历，参与设计、核心开发或产品交付；能独立承担技术模块并部署上线。只有模型 API 调用或简单 Demo 不满足原文的项目经历要求 |
| 必备核心能力 | 任务规划、工具调用、工作流与状态管理；主流 Agent 框架实际使用；模型能力边界、Prompt、Context、Tool Calling、Structured Output、评估与成本优化；Transformer、Embedding、RAG 的基本原理及场景 |
| 明示优先 | 985/211 或相关优势学科背景，优秀项目经验可适当放宽；复杂 Agent 产品、浏览器操作、算法与模型优化、海外 C 端及电商经验 |
| 加分项 | AI 开源贡献、独立发布产品或工具，以及相关 Agent 产品的深度使用或二次开发 |

LangGraph、OpenAI Agents SDK、Claude Agent SDK、AutoGen 是框架举例，不要求全部使用过。RAG、Memory、多 Agent 出现在「结合业务需求探索」的职责中，不能转成必须具有全部项目经历。页面的 3–5 年与正文的经历要求分别保留，具体年限口径待确认。

准备先完成真实项目与任务执行主线（P0），再补后端交付和研发协作证据（P1），最后按真实经历选择优先方向（P2）。P1 仍属于岗位职责；下列业务一致性、权限、故障测试等是为完成职责推导的准备问题。没有简历或实操评估，不据此判断当前能力。勾选只记录准备完成情况，不改变知识库学习状态。

## P0：真实 Agent 项目与独立交付

对应：「必须具备实际 AI Agent 项目开发经历」、独立负责模块、产品开发和部署上线。

- [ ] **讲清真实项目与个人贡献**：用户是谁、任务是什么、使用到哪一步？设计、核心代码、系统集成、测试和部署中，自己负责哪些部分，哪些由团队或框架提供？
- [ ] **沿一次任务展示工程深度**：从请求、模型决策、工具执行、业务状态到用户反馈，指出实际接口、数据和故障处理位置；结合[[agent-design-interview|Agent 设计主线]]复盘取舍。
- [ ] **提供一次优化证据**：原失败现象或性能问题是什么，如何定位、修改和验证？说明样本、时间窗口和比较条件，无数据时保留可核查的任务记录。

完成证据：项目介绍、架构与个人负责范围、一次完整任务记录及一项上线或优化材料。练习可补动手过程，真实项目经历仍须单独提供；学历和工作背景按实际履历核对。

## P0：任务规划、状态与异常恢复

对应：Agent 系统设计与开发；必备 Agent 开发能力；复杂任务的可靠性、执行效率和实际优化。

- [ ] **拆解一个购物任务**：以「在预算内比较候选商品，用户确认后下单」为自拟场景，怎样理解偏好、补问缺失条件、拆分搜索与比价，并判断任务完成？哪些步骤适合固定流程，哪些由模型决策？
- [ ] **说明框架与状态设计**：选择实际使用过的一个框架，说明执行入口、工具、任务调度和状态保存怎样配合；用户修改预算后，哪些结果继续有效、哪些需要重新查询？
- [ ] **推演中断与恢复**：搜索失败、外部请求超时、用户取消或进程重启时，从哪里继续？结合[[agent-checkpoint-interview|Checkpoint]]区分程序执行位置与实际订单结果，如何确认哪些动作已经生效？
- [ ] **解释停止与结果反馈**：任务无法满足预算、连续失败或超过时间与费用约束时，怎样结束、请求人工介入或返回部分结果？

完成证据：任务状态图、关键持久化位置，以及正常、改需求、失败、重启和取消的任务记录。能指出框架提供了什么、自己还承担哪些业务处理。

## P0：模型、Prompt、上下文与结构化输出

对应：LLM 应用开发与模型集成；必备大语言模型应用能力。

- [ ] **说明模型接入与能力边界**：任务需要哪些模型能力，如何选择调用方式？模型拒绝、输出不符合格式或工具参数无效时，程序怎样识别并处理？
- [ ] **组织可靠的模型输入**：Prompt 如何表达任务和约束，Structured Output 怎样检查字段与业务含义？用[[agent-context|上下文管理]]说明购物偏好、候选商品、历史操作和最新报价怎样进入当前调用，历史过长时保留什么？
- [ ] **解释基础原理与适用场景**：Transformer 与 Embedding 在所用模型、检索流程中分别承担什么作用？[[rag-workflow-interview|RAG 的资料从哪里来、怎样检索并参与生成]]；什么情况下应查询实时商品接口？
- [ ] **判断是否需要额外机制**：Memory 应保存哪些偏好、怎样更新；RAG 或多 Agent 针对什么实际问题，如何比较加入前后的效果和成本？允许结论是当前任务尚不需要。

完成证据：模型选择与失败策略、输入输出样例及一次上下文或提示词改动的对照记录。框架、提示词或模型变化的效果需要验证，不能仅凭接入成功判断。

## P0：商品、订单、支付与外部工具集成

对应：工具链与业务系统集成，商品搜索、价格查询、订单、支付，以及外部不确定性下的异常、重试与人工确认。

- [ ] **定义业务工具契约**：搜索、报价、创建订单和支付分别接收什么、返回什么？按[[tool-calling|工具调用]]检查参数、调用结果和错误，商品规格、币种、运费、库存与报价时间怎样影响比较？
- [ ] **划清用户确认范围**：哪些操作可自动执行，哪些需要确认？确认绑定哪个商品、数量、金额与有效期，价格变化后如何重新确认？用户授权和程序执行校验分别放在哪里？
- [ ] **处理结果未知与重复操作**：创建订单后连接断开，如何查询是否已成功？重复点击、重复回调、重试或恢复时，如何识别同一笔业务操作并检查最终结果？
- [ ] **比较 API 与网页操作**：外部系统有接口或仅能通过页面操作时，怎样组织调用、检查结果、处理登录失效与页面变化？浏览器具体实现经验属于原文优先项，核心职责仍需要能说明外部集成方案。

完成证据：工具接口与权限说明、订单/支付状态设计，以及「成功、失败、结果未知、重复操作、确认后价格变化」的处理记录。可使用受控模拟服务或测试环境，明确哪些尚未连接真实业务。

## P1：后端架构、部署与线上排查

对应：用户、商品、订单、支付模块开发；数据库、缓存、异步任务；部署、监控与线上问题排查。

- [ ] **说明模块与数据边界**：用户身份、购物任务、商品快照、订单和支付记录怎样关联？哪些数据由外部系统确认，哪些由本地服务维护，接口失败后怎样协调？
- [ ] **解释存储和异步设计**：哪些数据需要事务保护，哪些可以缓存，长任务怎样入队、查询进度和处理失败？缓存数据变旧、任务重复投递或并发增大时如何验证？
- [ ] **准备部署与诊断过程**：配置、凭据、数据变更、发布和回滚怎样管理？一次任务变慢或失败，如何区分模型、工具、数据库和外部服务的问题？

完成证据：后端模块图、关键表与接口说明、部署步骤，以及一次基于记录或指标的故障定位。技术栈以实际经历为准，原文没有指定必须使用 Go、某种数据库或消息队列。

## P1：效果评估、成本与 AI 协作研发

对应：任务完成率、效率、稳定性与模型成本优化；评估测试机制；AI-Native 研发、原型验证及业务结果。

- [ ] **明确购物任务怎样算成功**：按[[agent-evaluation-interview|结果与过程评测]]区分推荐是否满足约束、操作是否实际完成、是否重复下单或越权；工具失败和信息不足怎样进入评测集？
- [ ] **比较质量、效率与成本**：同批任务下怎样记录完成率、耗时、模型与外部调用费用？调整模型调用、上下文或工具策略后，怎样发现质量下降、费用转移和偶发失败？
- [ ] **展示 AI 编程与书面协作**：选择实际使用过的 AI 编程工具，说明任务如何拆分、代码怎样审查和验证；用一份简短书面说明交代原型目标、结果与下一步产品决策。

完成证据：代表性任务与失败用例、一次改动前后比较，以及真实研发片段或书面交付材料。原文要求深度使用 AI 编程工具，不据此要求列举的每款工具都精通。

## P2：按已有经历选择优先方向

- [ ] **复杂 Agent 产品**：真实用户、多步骤执行、长任务状态与恢复、评估体系建设中，选一项给出设计和优化证据；与基础必需项目经历区分深度。
- [ ] **浏览器与 Computer Use**：有 Playwright、Puppeteer 等经验时，复盘动态页面、复杂交互、动作结果校验和异常处理。
- [ ] **算法与模型优化**：有 NLP、机器学习、微调、推理优化、RAG 或 Agent 策略优化经验时，说明数据、基线、改动、效果和代价，不把列举方向全部转为必学任务。
- [ ] **海外产品与电商**：有跨境、商品搜索推荐、订单支付或 Stripe/PayPal 集成经验时，指出具体负责范围与业务约束；原文未要求两家支付平台都使用过。
- [ ] **开源与独立发布**：准备可核查的仓库、贡献、插件或产品；有 OpenClaw、Claude Code、Codex 等深度使用或二次开发经历时，说明具体问题与实现边界。

面试前仍需确认招聘主体与产品团队关系、年限口径、现有技术栈、实际自动下单和支付范围、海外网站接入方式，以及岗位在产品与后端之间的职责比例。
