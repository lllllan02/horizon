[[kv-cache|KV Cache]] 是大模型推理时，保存已处理 Token 在各注意力层中产生的键（Key）、值（Value）向量的缓存。后续推理可以复用这些中间结果，减少重复计算。

Agent 多轮调用会反复携带系统提示词、工具定义和历史消息。服务支持跨请求前缀缓存时，可以复用相同开头对应的 KV，因此调用方提高命中率的核心是「**保持前缀稳定**」。前缀需要按 Token 精确匹配，前面一处改动就会影响从该处开始的后续复用，语义相同也不够。

保持[[kv-cache-sources#Agent 怎样保持可复用前缀|前缀稳定]]，主要有几种做法：

1. **固定拼接与序列化方式**：系统提示词、工具定义和历史消息按固定规则组织，具体顺序遵循接口要求。工具列表、参数定义和序列化结果保持稳定，避免每轮无意义地换序、改写或增删工具。
2. **静态内容靠前，动态内容靠后**：固定指令、公共背景尽量放在前面；本轮问题、检索结果等变化内容放在后面。当前时间、请求 ID 不要混入固定提示词开头，无需模型理解的信息不送入上下文。
3. **历史尽量只追加**：新消息、工具调用和结果接在已有历史之后，避免回头改写旧消息、调整顺序，或每轮把最新任务状态覆盖进前面的固定提示词。
4. **按需裁剪和压缩**：不要仅为省少量 Token 就每轮[[context-trimming|裁剪历史]]或[[context-compaction|重写摘要]]，这会改变前缀、增加重新计算。接近输入预算或无用历史明显影响效果时仍应处理；处理后保持新摘要与保留历史稳定，继续追加，权衡缓存重建与后续输入的成本。

跨任务复用公共提示词、模型与实例的缓存路由也可作为补充优化。实际命中还取决于[[kv-cache-sources#接口怎样决定是否命中|缓存有效期、隔离范围等服务条件]]。
