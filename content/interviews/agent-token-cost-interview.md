我会先统计整次任务的费用，再结合评测和执行链路，找出可以优化的环节。

1. **费用记录与汇总**：记录每次模型调用的 usage，包括模型、输入输出 Token 和缓存信息，按[[agent-token-cost-sources#计费口径|对应计费类别与单价]]计算费用，再汇总整个 Agent 任务。重试和子 Agent 的调用也要计入；工具调用外部 API 等产生的费用，另外统计后一起汇总。

2. **评测集与链路分析**：从线上真实任务或典型业务场景整理[[agent-evaluation|评测集]]，结合线上抽样的 [[agent-trace|Trace]]，看完整执行过程，判断成本集中在哪里、哪些步骤存在浪费。

3. **减少用量与无效调用**：一方面精简提示词、历史上下文和[[tool-result-interview|工具返回结果]]，减少单次 Token；另一方面改善提示词、工具描述和结果反馈，减少选错工具、重复查询和无效重试，从而减少不必要的 Agent 循环步数。

4. **尝试低成本模型**：对不同任务或步骤做模型对比评测，在质量达标的环节使用更便宜的模型，复杂步骤保留能力更强的模型。公共提示前缀重复较多时，也可以评估提示缓存的收益。

优化后，用同一套评测比较成功率、质量、延迟和[[agent-token-cost-sources#怎样确认降本有效|每成功任务成本]]，确认费用下降的同时，任务完成效果仍然达标。
