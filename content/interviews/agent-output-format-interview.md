我会先约定输出格式，再考虑模型的结构化输出能力；如果还需要同时交付业务数据和文字回复，就把数据提交交给工具。

1. **通过提示词做软约束，并在解析时补救**：明确要求返回 JSON，提供字段说明、JSON Schema 和示例，不要 Markdown 围栏或额外说明。但这些仍然是软约束，模型可能不遵守。夹带说明时可以尝试提取其中的 JSON；缺引号、尾逗号等语法问题可以尝试 [[jsonrepair-summary|JSON repair]]。提取或修复后仍要校验，不能保证每次都成功，也不能保证恢复了原意。

2. **模型支持时，在调用中指定结构化输出**：确认模型和服务支持后，通过接口参数约束生成格式。还要区分 [[openai-structured-outputs#JSON mode 与严格 Schema 有什么区别？|JSON mode 与严格 Schema 约束]]：前者主要保证 JSON 语法；需要字段与类型也符合要求时，使用 `json_schema`、`strict: true` 等相应配置。

3. **需要业务数据和自由文本分开交付时，通过工具提交结果**：让模型把程序需要的数据作为工具参数提交，由程序校验并保存；确认成功后，再让模型正常输出文字建议。[[learning-plan-agent-submission|学习计划 Agent 提交题目清单]]就是这个做法。[[openai-structured-outputs#工具调用严格约束什么？|严格工具调用]]可以约束参数结构，保存是否成功仍由程序判断；它也可以和结构化约束一起使用。

前面这些办法主要约束的是 JSON 的输出格式与结构。**格式正确不代表里面的内容和语义正确**，所以程序拿到结果后，还需要进一步检查字段名称、类型、必填项、枚举值和取值范围，并校验是否符合业务规则。

程序还要检查拒绝和截断；可修正的错误在预算内重试，持续失败就明确结束或降级。具体见[[tool-calling-interview|参数校验与失败处理]]。
