Kafka 保证**「分区内有序，分区之间不保证顺序」**，也就是同一个 Partition 中的消息可以按写入日志的顺序读取。

如果想保证同一个业务对象的消息有序，比如同一个订单的创建、支付、取消事件，可以用订单 ID 作为 Key。在分区策略一致、按 Key 路由，并且分区数量不变的情况下，相同 Key 的消息会进入同一个分区。

同时，生产端和消费端也需要保持这些消息的发送、处理顺序。**「按顺序读取，不等于按顺序完成处理」**，比如消费者读出来后再交给多个线程并行处理，完成顺序仍可能改变。

另外，[[kafka-partition-count-sources#在线新增分区改变了什么|在线增加分区]]可能改变 Key 的路由。同一个 Key 的旧消息仍在原分区，新消息可能进入另一个分区，两边独立消费就可能先处理新消息。所以有严格顺序要求时，需要额外设计扩容期间新旧消息的衔接与切换方案。
