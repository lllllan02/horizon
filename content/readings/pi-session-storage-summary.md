**「Pi 用 JSONL 保存会话条目，再从当前分支构建模型输入。」** 本文聚焦官方 Session File Format 中的存储结构与读取链路，依据 2026-10-11 的 latest 文档。

## 文件里有什么？

会话文件位于 `~/.pi/agent/sessions/`，按工作目录组织。首行保存会话 ID、格式版本等信息；后续每行通过 `type` 区分消息、压缩、配置变化等条目。

普通条目带 `id`、`parentId` 和时间，消息正文放在 `message` 中。工具结果保留调用 ID、工具名、内容与错误标记；系统消息还能记录提示和工具配置的变化。因此，文件不是只有用户和助手文本的聊天转录。

## 分支与压缩怎样影响读取？

`parentId` 表示前驱关系，同一个文件可以包含多条分支。读取时沿当前叶节点追溯路径，不能把文件中所有行直接拼成一段对话。

上下文构建还会应用当前路径上的压缩记录，用摘要与保留起点选择内容；上下文编辑可省略或替换模型可见内容，而不改写所选原始条目。用量等管理记录不作为普通消息传入模型。

可借鉴的分工是：**「会话文件保留记录，读取逻辑决定当前分支与模型可见内容」**。JSONL 是 Pi 的具体选择，其他存储也可以表达同样的关系。
