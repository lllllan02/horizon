**「LangChain 把模型调用中的指令、消息、工具和输出格式分别作为可调整对象，按当前任务组装请求。」** 本文聚焦官方指南的 Model context 部分，依据 2026-10-11 页面；不展开工具执行与生命周期中间件的全部接口。

## 输入从哪里来？

指南区分会话内的 State、跨会话的 Store，以及运行时配置 Runtime Context。这是数据来源的划分，不是三段必须放进提示词的文本；连接、凭据等运行依赖也不必暴露给模型。

模型调用所需的指令、消息和工具，可以从这些来源分别选取。例如根据当前运行条件调整指令，从状态读取上传文件信息，或从长期存储取出相关偏好。

## 怎样改变本轮输入？

文档使用中间件修改模型请求：动态提示生成当前指令，消息处理补入相关材料，工具处理决定本轮提供的能力。模型选择与输出格式也可独立配置；这些配置不等同于普通对话文本。

关键区别是：**「修改一次调用中的消息或工具，不一定修改持久状态」**；工具写入和生命周期处理则可以改变后续仍会保存的数据。因此，模型可见输入与底层存储应分别理解。

可借鉴的是按职责选择和更新输入。文档没有规定所有 Agent 都采用相同层数，也没有把这些对象列成重要性或指令权限的排序。
