**「LongMemEval 检查跨会话事实记忆，并用索引、检索和阅读三个阶段分析失败；V2 扩展到 Agent 对环境与工作流程的经验。」** 本篇依据原论文 v2 与 2026-10-13 核对的两个官方仓库，未运行 benchmark。

## 对话记忆评什么？

[原基准](https://github.com/xiaowu0162/LongMemEval)的 500 道问题覆盖信息提取、跨会话推理、知识更新、时间推理和信息不足时的拒答。历史按顺序提供；部分问题需要记住助手先前给出的内容，不能只保存用户偏好。

S 设置每题约 115K Token，M 设置约 150 万 Token。数据提供会话日期、问题日期与证据位置；oracle 设置只给证据会话，可与完整历史对照，但差值不能独立定位每个组件。

## 论文如何把问题落实到设计？

[第 4—5 节](https://arxiv.org/html/2410.10813v2#S4)分别改变四处：

| 控制点 | 比较或做法 | 论文中的主要观察 |
| --- | --- | --- |
| 保存粒度 value | 整会话、对话轮次、抽取事实 | 轮次粒度减少混杂；只存事实可能丢细节 |
| 检索入口 key | 原文加抽取事实形成多个入口 | 让原文中不突出的信息更易被找到 |
| 查询 query | 从问题提取时间范围 | 时间条件可缩小无关候选，但依赖解析准确性 |
| 阅读方式 | 结构化证据、先提取要点再回答 | 找齐证据后仍需处理模型如何使用它 |

这组实验说明**「检索用什么表示」**与**「最终读什么内容」**可以分开。保存完整片段、用更短事实辅助索引，能避免过早把原文压成唯一事实短句。收益属于所测模型和数据，不表示每个系统都应采用同样粒度。

## 经验记忆评什么？

[LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2)提供 451 道人工整理问题，输入为较长的 Agent 交互轨迹，覆盖静态状态、动态变化、工作流程、环境陷阱与前提条件。评测同时关注答案与查询延迟。

其接入协议将轨迹写入与查询分开：记忆后端返回文本或图像上下文，由固定阅读模型回答；查询侧不提供标准答案等评测元数据。这样比较的是记忆对同一阅读器的帮助，而非让各系统任意更换回答模型。

## 怎样迁移到自己的评测？

用上述能力构造业务用例，固定模型、历史、初始记忆和预算，**「区分证据召回与答案正确性」**。数据、评分和 V2 协议应固定版本；QA 成绩不能直接代表工具执行成功率、权限隔离或删除有效性，这些仍需独立验证。
