**「Anthropic 将工具使用的三个瓶颈分别交给工具搜索、程序化调用和使用示例处理：减少无关定义、减少中间数据、减少参数误用。」**

## 定义太多：按需搜索

全部工具定义预先进入上下文，不仅占 Token，相近的名称和描述还会干扰选择。文章保留少量常用工具，其余标记为延迟加载：模型搜索 → 返回工具引用 → 展开完整定义 → 正常调用。

**「延迟的是进入模型上下文的时机」**，定义仍需提供给 API。搜索也增加一次交互，工具少、定义短时未必划算。

## 调用太碎：让代码处理中间结果

程序化工具调用（Programmatic Tool Calling）让模型编写 Python，用循环、分支、并发和筛选组织多次调用。应用仍执行外部请求并回传结果，但**「中间数据交给代码处理，最终输出才进入模型上下文」**。

原文的费用检查例子是：获取团队成员 → 批量查询费用 → 按预算筛选 → 只返回超支者。收益来自减少模型往返和无关结果，而非消除外部调用；若每一步都需要模型理解中间结果，收益就会减弱。

## 参数易错：用示例表达惯例

Schema 能约束类型，却难以完整表达可选参数如何搭配、业务标识如何填写。工具使用示例补足这些信息，同时也占用上下文。

三者可组合，但应从实际瓶颈出发。本文记录 2025-11-24 原文的设计；文中的内部评测与 API 配置不代表所有任务和后续版本。
