Azure 的切分文档比较固定长度、按结构或语义变化切分，以及混合策略。本篇节选切分方法与参数实验；API 状态依据 2026-10-13 阅读页面，示例未本地运行。

## 小块与大块改变什么？

切分要让输入适合 embedding 模型，并**「让每块能表达可检索的信息」**。固定长度容易实现，但可能割裂句子；按段落或标题切分更贴合文档结构，却仍需处理超长段。重叠可以保留边界附近的上下文，同时增加块数、索引量与重复结果。

官方用同一份 NASA 电子书比较不同长度和重叠量；改变参数后，块数明显变化。因此块长同时影响检索单位与存储成本，不只是模型窗口上限。

## 参数不能脱离计量单位

Text Split 的 `pages` 是文本分块模式，不等于 PDF 的物理页。页面长度可按字符或支持的 token 模式度量；字符数不能直接当 token 数。原文同时展示字符参数和 tokenizer 统计，提醒读者依据实际内容调整。

文档中的起始配置适用于其示例，**「不是中文、代码和表格的统一最优值」**。工程比较应固定问题集，观察证据是否被割裂、找回后是否完整以及送入生成模型的总长度。
