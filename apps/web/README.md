「视界」（Horizon）的 Web 应用是本地文档阅读页面，首页移植 [Galaxy View](https://github.com/Longwind1984/galaxy-view) 的三维星空渲染、辉光、星云背景和镜头控制。每颗文档星点对应一篇笔记，连线来自真实正文引用；背景星点仅用于装饰，不参与文档计数。正文直接读取 `content/`，不维护第二份内容。页面外壳和阅读面板沿用 [Neural Creator Dashboard](https://github.com/luoluo-121/neural-creator-dashboard) 的适配实现。项目介绍见 [[README|README]]。

## 统计看板

首页使用星图，Dashboard 使用独立哈希路由：`#/dashboard` 为学习概况，`#/dashboard/activity` 为变更记录，可直接打开、收藏并刷新。两页通过左侧导航切换，手机使用顶部导航；刷新保留当前看板视图，浏览器前后退也会恢复对应页面。点击「返回星图」或「返回阅读」回到原视图；从正文进入看板后刷新，仍可返回该文档。所有内容来自当前启用目录，本地随文档同步，Pages 显示最近一次构建的快照。

面板名称在导航中显示，内容区只保留辅助技术使用的隐藏一级标题，不再重复大标题、说明和底部品牌行。桌面布局随窗口高度调整；变更记录的长明细在列表内滚动，少量内容无需整页滚动。手机保留自然的内容滚动和日期触控尺寸。

「学习概况」以继续阅读为首要入口，采用开放排版：主阅读区使用更大的标题、摘要与主要按钮；书架和三态数量放在桌面右侧，小屏依次显示，状态数量仅作当前文档构成的摘要。主阅读区展示本机最后打开的文档、摘要和最多两篇显式配置的阅读建议；没有本机记录时使用阅读中列表的首篇，再无内容时引导浏览星图。阅读书架可切换阅读中和最近打开，排除主阅读区已展示的文档，默认展示三篇并可展开。阅读中按进入该状态的时间排序，最近打开仅使用当前浏览器记录。

概况下方的专题与近期变化使用较轻的标题和图表，以留白和细分隔线组织，不分别包成卡片。专题用堆叠状态条展示文档最多的五个专题，各条均以该专题总量为分母，点击打开原有星图中的对应分类；数量表示内容构成，不表示掌握率。近 14 天变化以每日去重文档／配图数绘成柱图，点击进入对应日期；摘要中的文档数按整个区间去重。

「变更记录」使用月历和当天时间线，共用目录与活动类型筛选。月历支持上／下月、回到今天、点击日期与方向键跨日跨月选择，未来日期不可选。每天按不同文档／配图去重计数，明细合并同一天同一对象的同类记录，迁移保留不同方向，并在来源与目标目录都可见，全局只计一次。当天明细每次展示 20 条，可继续展开；每条标明来自文档日期或检测记录。时间统一为北京时间。

本地服务加载文档时比较快照，将检测到的新增文档、正文或标题修改、目录迁移、学习／阅读状态变更、配图新增与更新、新增图片格式保存到 `content/.activity.json`。首次加载只建立现状基线，并从明确填写的 `created_at` 与最后一次 `updated_at` 回填文档日期；不会把全部既有图片当作当天新增，也不使用文件修改时间或提交时间推测历史。历史文档日期按回填时的目录归类，不能还原完整修改过程。服务未运行或页面未刷新期间的变化归入下次检测时间，多次保存或往返迁移可能合并；重命名改变文档 ID 时按新出现的文档处理。备份时应包含活动记录文件，其中仅保存事件和内容摘要哈希，不复制正文。

配图记录覆盖 `content/assets/` 内的 PNG、JPEG、WebP、GIF、SVG 和 Excalidraw 文件，同路径同名的不同格式归为一组。新增格式仅表示新文件被检测到，不证明执行过转换。目录归属取检测时引用配图的文档；未关联图片只在全部范围显示。静态构建只读取历史，不产生检测事件，仅导出当前收录文档及其所引用配图的活动，省略图片源文件清单；已删除或不再收录的文档历史不展示。

记录文件采用临时文件替换和互斥锁；损坏或锁未释放时保留原文件，阅读继续可用，时间记录回退到文档日期并提示异常。如服务异常退出遗留 `content/.activity.json.lock`，确认没有服务正在写入后可移除空锁目录。无记录不等于没有变化；学习状态、文档数量与文件活动均不用于推算学习时长、连续学习天数或掌握程度。

项目品牌配置位于 `src/config.ts`：中文名为「视界」，英文名为 `Horizon`；首页、加载提示、统计看板、运行时网页标题和启动日志共用该配置。`index.html` 的初始标题保持同名。

浏览器阅读历史和页面状态使用 `horizon:*` 存储键与 `horizonReading` 历史状态字段，不读取或迁移旧品牌下的记录。存储键包含访问路径，不同路径的阅读状态相互独立。

## 手机阅读与阅读建议

文档标题文字右下侧提供复制图标，与标题同行，不额外占用一行。无需选中文字即可复制项目名、文件路径、文档标题与「整篇文档」范围，粘贴给 Codex 后可直接补充整篇修改要求。复制结果复用页面顶部的状态气泡，自动消失，不占用标题空间。

选中正文文字后，阅读卡片底部出现「复制纯文本」和「复制引用」。纯文本保留选中文字；引用标明 Horizon 项目、相对项目根目录的 `content/` 文件路径、文档标题、章节层级和选中内容的 Markdown，保留列表层级、内部链接目标、强调、表格和代码格式，跨章节时标明起止章节。内部双链保留原有写法，部分选中链接时保留目标与所选文字；不复制链接图标、外链箭头或代码按钮等网页装饰。省略重复目录和本机阅读链接，可直接粘贴给 Codex，再补充具体问题或修改要求。取消选择、点击其他位置或按 Escape 收起选区操作；Escape 优先收起选区操作，不关闭文档。

阅读卡片顶部的「字号」可选择 85%、100%、115%、130% 或 150%，同步调整正文、标题、表格与代码。100% 恢复默认大小；选择保存在当前浏览器，切换文章和刷新后继续沿用。手机端默认正文为 16px，表格与代码为 13px。

宽度不超过 900px 时，打开文档自动全屏显示正文，工具栏保留关闭、阅读列表与状态操作。点击「打开阅读列表」查看建议阅读列表，点击「返回正文」保留原滚动位置；选中文档后回到正文。关闭文档返回星图。桌面端继续使用左侧列表与右侧阅读卡片。

宽度不超过 600px 时，工具栏分为两行：上行显示文档归属、阅读列表与关闭，下行显示字号与状态操作。首页搜索聚焦后移至上方，随机复习标题与搜索分行显示；看板使用顶部视图导航与适配小屏的月历。页面留白考虑屏幕安全区域。

每篇文档可在 YAML 属性中维护可选的 `reading_suggestions` 有序数组，从正文已有内部链接中选择希望依次阅读的文档：

```yaml
reading_suggestions:
  - agent
  - multi-agent
```

使用唯一文件名，不含 `.md`；解析器也兼容别名、路径和带引号的双链。建议以整篇文档为单位，不跳转到章节。阅读面板提供「建议阅读」入口，列表按配置顺序显示序号，不向正文插入清单。列表顶部可在「建议阅读」与「阅读中」间切换，支持拖动、滚轮与方向键；阅读中显示文档状态为 reading 的内容。列表不提供类型、状态筛选，默认显示建议阅读。未配置时建议列表为空，不推测阅读顺序。

重复目标只保留首次出现；缺失、歧义、自引用或未出现在正文有效内链中的目标不展示，并通过检索巡检报告。仅出现在 `parent` 中的目标不算正文内链。建议不新增图谱连线或反向链接，也不修改学习、阅读状态。本地同步和静态导出使用相同解析逻辑；修改建议仍直接编辑 Markdown 属性。

## 开发与类型检查

应用使用 React、Vite 和 TypeScript。`src/neural/main.tsx` 负责页面组合，`src/neural/useLibrary.ts` 连接 React 与 `src/data/library-store.ts` 的加载、轮询和状态写回，`src/data/library-client.ts` 统一接口请求；文档、图谱、阅读状态与组件契约集中在 `src/types/`。本地服务入口为 `server.ts`，静态导出入口为 `scripts/build-pages.ts`，通过 `node --import tsx` 运行，不依赖 Node 原生 TypeScript 支持。根目录检索入口为 `scripts/retrieve.ts`，通过 `npm --silent --prefix apps/web run retrieve -- <子命令>` 执行，直接导入共享解析模块。

在 `apps/web/` 运行 `npm run typecheck` 检查类型，`npm test` 运行回归测试，`npm run format:check` 检查格式，`npm run format` 格式化自有代码。`npm run build` 和 `npm run build:pages` 均先检查类型再构建。第三方移植代码保留原有排版。

类型检查覆盖应用、服务、构建脚本、根目录检索实现和 TypeScript 测试，启用完整 `strict` 模式（包含 `noImplicitAny`、`strictNullChecks`），并检查未使用的局部变量与参数。文档结点与导航结点、DOM 引用、异步状态和可空数据均通过共享类型或使用位置的约束表达。迁移保留既有界面、文件内容来源与行为。

接口 JSON 和浏览器记忆从 `unknown` 开始校验，文档库的嵌套字段由 `src/data/library-schema.ts` 检查；损坏的界面记忆回退到默认值。图谱以 `nodeType` 区分完整文档与结构节点，状态写回操作以 `status` 区分空闲、处理中、成功和失败。读取请求不重叠，状态写回和卸载会取消旧读取，迟到结果不能覆盖新状态。

本地服务通过 `createLibraryLoader` 缓存文件解析结果，每轮检查文件路径、大小、inode、mtime 和 ctime。状态写回复用同一缓存；纯状态变化只重新渲染目标及引用它的文档，其余正文对象保持复用。未变化时复用快照；出现新增、修改、删除或移动时重新生成全部引用关系，避免别名、parent 与入站引用失效。失败的解析不会写入缓存。条件请求使用包含文档和活动版本的 ETag，内容未变时返回 304。静态导出、状态写回校验和检索命令仍使用独立的完整加载，正文只保存在 Markdown 文件中。

首页的场景创建与释放放在 `useGalaxyScene.ts`，星点标签放在 `GalaxyLabels.tsx`，面板尺寸同步与卡片阅读过渡分别放在 `useReaderLayout.ts`、`useReadingFlight.ts`。修改这些模块仍需按下文的整屏验收要求核对共同进度。

星点标签与阅读路径通过 `scene-overlay.ts` 单独订阅动画投影，不带动正文、搜索和看板重渲染；相同投影不重复通知。本地轮询显式处理 ETag，304 直接复用已验证的文档对象，避免每四秒重新解析整库。三维画布与后处理缓冲共用最多 300 万像素的预算，星图绘制最高 60 帧，阅读过渡结束后最高 30 帧；手机全屏正文遮住星图后暂停场景计算与绘制，关闭正文或切换文章时恢复必要的过渡。后台标签页跳过绘制，看板入口释放三维资源。

排查卡顿或崩溃时，先对照近期改动，分别测量内容轮询、React 更新与 WebGL 负载，不能仅凭浏览器错误码认定内存泄漏。资源相关修改需覆盖高像素比、稳定阅读和多次看板往返，检查缓冲预算、重复解析及上下文释放；短时回归通过不等于已排除长时间运行或特定浏览器的崩溃。

浏览器回归使用 Playwright：首次运行 `npx playwright install chromium`，随后运行 `npm run test:e2e`。默认预览端口为 4176，端口占用时可通过 `HORIZON_E2E_PORT` 指定其他本地端口；测试结束会关闭临时服务并删除样例目录。测试在临时目录生成两篇样例文档并构建真实 Pages 应用，不读取或修改私人笔记；覆盖宽屏、窄屏、减少动态效果、搜索、双链跳转、历史导航、阅读刷新、看板往返、阅读过渡、四类 Mermaid 图表与损坏记忆回退。测试截图和失败追踪位于被 Git 忽略的 `test-results/`。另有本地稳定阅读回归，使用临时笔记验证连续写入期间的画布、正文、选区和滚动保持，以及主动更新与状态切换。浏览器回归用于验证交互，不能替代整屏目视检查。

检索命令以 `scripts/retrieve.ts` 为唯一实现，根目录运行 `npm --silent --prefix apps/web run retrieve -- query <词...>`；`make search q="..."`、`make index`、`make lint` 调用同一入口。`--silent` 去掉 npm 启动提示，便于直接解析 JSON 输出。参数错误返回 2，巡检发现错误或目标不存在返回 1，正常完成返回 0；`--limit` 必须为正整数，检索以 `--` 开头的文字时放在单独的 `--` 后面。CLI 复用 Markdown 解析和反链生成，关闭代码高亮，普通查询跳过反链计算，检索排序和片段格式保持一致。

`retrieve -- lint` 将 Markdown 表格内未转义的双链分隔符列为错误，返回 1；JSON 结果归入 `findings.table`。检查按实际表格块进行，普通正文和围栏代码示例不受影响。

项目级升级应沿入口、共享模块、脚本、测试、构建与使用说明检查调用链。保持功能不变不等于保留旧文件名或旧命令；没有实际外部兼容需求时，直接更新调用方并删除旧入口，不能仅为省去文档更新而保留适配层。

三维场景通过动态导入加载，Three.js 核心和 WebGL 渲染分别分包；Mermaid 仍只在正文包含图表时加载，共享代码按上游模块分包。`scripts/bundle-budget.ts` 在构建时检查普通 JS 包不超过 500 KB，并拒绝 Three.js 或 Mermaid 进入入口的静态依赖。上游预打包的 Mermaid 解析器与 ELK 引擎分别保留 700 KB、1.5 MB 上限；它们仍可能触发 Vite 默认的 500 KB 提示，不提高该阈值，也不通过删除图表类型减小体积。构建产物中的 `bundle-report.json` 记录实际大小、上限与入口静态依赖，超出预算会阻断构建。

## 启动与使用

需要 Node.js 22.12 或以上。在项目根目录执行：

```sh
make install
make
```

首次启动前用 `make install` 安装依赖，之后直接运行 `make` 或 `make run`。本机打开 `http://127.0.0.1:4173`。服务默认监听 `0.0.0.0`，同一局域网的设备可打开启动日志中的「局域网访问」地址（`http://这台电脑的局域网IP:4173`）；电脑防火墙需允许连接，路由器需允许设备互访。局域网内的设备可以阅读启用目录中的全部文档，学习／阅读状态写回仍只允许本机页面。可用 `make HOST=127.0.0.1` 限制为本机访问，`make PORT=4174` 更换端口，按 Ctrl+C 停止服务。页面与文档接口由同一个服务提供，开发模式沿用相同监听配置。

默认启动为稳定阅读模式（`npm start`）：首次启动构建前端，后续启动按源码、配置、素材、依赖锁文件及构建环境的内容摘要复用缓存；仅修改笔记不会触发前端重建。启动日志显示是否命中缓存和准备耗时。每个进程仍使用独占的临时副本，运行期间修改代码或另行构建不会触发阅读页热更新；要采用新代码，重启阅读服务并手动刷新页面。正常关闭会清理进程副本，构建缓存保留在 `apps/web/node_modules/.cache/horizon-reader/`，可随时删除，`make install` 也会清除。内容接口仍读取当前 Markdown，状态切换功能仍可用。

缓存缺失或损坏时自动重建。需要强制重建时运行 `npm --prefix apps/web start -- --rebuild`；直接修改 `node_modules` 内依赖文件后也应强制重建。源码、配置或素材变化后的首次启动仍需完整构建。

开发界面时使用 `make dev PORT=4174`（或在应用目录运行 `npm run dev`），在另一端口启用 Vite 热更新。阅读服务与开发服务可同时运行；代码修改只自动影响开发页面。

每篇文档只使用一个 `category`，未填写时归入「未分类」；分类按名称排列，不由目录决定。`tags` 参与检索，`type`（兼容 `classes`）表达文档类型。

常见操作统一使用细线图标：代码块以复制图标提供复制功能，成功后短暂显示勾选；最近阅读、关闭和专注阅读使用图标按钮并保留无障碍名称与悬停提示。复制文档保留「标题 / 全文」以区分范围；元信息、标签和目录减少边框与背景，悬停、键盘聚焦和选中状态仍可辨认。

正文与悬浮预览支持 `mermaid` 代码围栏中的流程图、时序图、状态图、类图、实体关系图和甘特图等 Mermaid 图表。图表采用深色主题，宽图可在图内横向滚动；下方「查看源码」可展开原文，正文图表顶部可复制源码。语法错误或组件加载失败时保留源码并提示。图表组件在遇到图表时才加载，由项目依赖打包，不依赖外部渲染服务；本地与 Pages 使用相同的渲染方式。语法参见 [Mermaid 官方文档](https://mermaid.js.org/intro/)。

点击正文中的图片或已渲染的 Mermaid 图表可放大查看，也可用 Tab 聚焦后按 Enter 或空格打开。弹层默认适应窗口，支持放大、缩小、原始大小和滚动查看细节；点击空白处、关闭按钮或按 Esc 返回正文，保留阅读位置。窄屏使用相同操作，弹层打开时不会触发正文的前后篇切换快捷键。

位图嵌入可用 `![[assets/image.png|480]]` 指定正文显示宽度，使用正整数像素值；高度保持原图比例，窄屏自动缩小到容器内。未指定宽度时沿用原有显示，源文件与放大预览保持原始分辨率。支持范围和写法见[[docs/metadata-and-links#链接与合并|附件语法]]。

```yaml
---
title: "RAG 检索评测"
category: "RAG"
tags: ["Agent", "检索", "评测"]
---
```

该文档归入 RAG 分类，标签参与搜索。category 是本项目约定的自定义文本属性，填写一个分类名称；Obsidian 内置属性包括 tags、aliases、cssclasses，其中 cssclasses 用于样式。[官方属性说明](https://obsidian.md/help/properties)

导航栏使用银灰色黑洞标志 `public/black-hole-logo.png`，保留倾斜光带和柔和亮边，通过屏幕混合融入深色背景，不额外叠加辉光。网页标签 `public/black-hole-favicon.svg` 直接从导航栏图片导出：将亮度转换为透明度、去掉外围空白并缩至 64 像素，适度提升整体轮廓和中间倾斜光带的对比，不另画图形。SVG 内嵌透明 PNG，浅色系统主题使用黑色，深色系统主题使用白色。

## 目录配置

[collections.config.json](collections.config.json) 是收录目录和视觉标识的唯一配置入口。本地文档读取、静态导出、Agent 检索、目录分组、搜索标记、正文与预览图标、列表端点和三维星点共同使用它。新增一项并在 `content/<id>/` 放入 Markdown 即可，无需增加目录判断分支；空目录不显示虚构的分组。

例如增加参考目录：

```json
{
  "id": "reference",
  "label": "Reference",
  "description": "参考资料",
  "enabled": true,
  "icon": "M4 3h16v18H4Z M8 7h8 M8 11h8",
  "color": "#d6b7ed",
  "marker": {"shape": "diamond", "hollow": true},
  "node": {"size": 1, "halo": 1, "rays": 1, "rayStretch": 1, "rayAngle": 45}
}
```

- `id` 对应 content 下的单层目录，只接受小写字母开头的字母、数字和短横线，不能重复。
- `label`、`description` 用于显示名称和图标说明；`icon` 是 24×24 SVG 的 path `d` 数据，不接受整段 HTML/SVG。
- `color` 是六位十六进制颜色，用于目录分组、星点近核与列表标记。
- `link` 可省略，控制正文、嵌入摘要标题与悬浮预览中的内部链接，独立于星点的 `color`。例如 `"link": {"color": "#acd2fa", "opacity": 0.26}`；`color` 是六位十六进制颜色，同时用于文字、图标和荧光笔，`opacity` 是底色浓度（0–1）。省略时使用薰衣草紫色 `#c9b4ee` 和浓度 `0.24`，悬停或键盘聚焦时加深底色。任意目录均可配置；状态样式会在对应文档上覆盖这些基础参数。
- `marker` 可省略，默认实心圆；`shape` 支持 circle、diamond、square，`hollow` 控制空心。
- `node` 可省略：size 控制尺寸（0.5–2），halo、rays 控制光晕与星芒强度（0–2），rayStretch 控制横向星芒长度（0.5–2），rayAngle 控制星芒旋转角度（−180–180）。默认依次为 1、1、1、1、0。颜色和节点参数同样适用于选中、预览与聚焦；减少动态效果设置继续生效。
- `enabled` 默认 true。设为 false 或移除配置会停止收录，原文件不会删除；引用该目录的链接可能变成未解析，应同步维护。配置错误会报告对应项，不静默忽略。

修改配置后重启本地服务；静态站点需重新构建。启用目录属于收录范围，不代表获得公开授权。全部启用目录共用三种学习状态及本地状态写入能力。日后新增目录只需编辑配置；引入超出已有参数的全新渲染效果才需修改渲染代码。

## 文档与边界

文档平铺在启用的 `content/<id>/` 目录，默认 notes、interviews、readings 与 glossary；读取器兼容递归读取，未配置或停用的目录不收录。目录由路径生成，状态由属性生成。title 缺省时显示文件名；别名参与检索，type 优先、兼容 classes；摘要缺省取正文开头，未知日期不补造。只读检索层 `scripts/retrieve.ts` 复用 `src/library.ts`，覆盖相同的启用目录范围。

有清晰上下级关系时填写 `parent: agent-sandbox`，直接使用单个主要上级的文件名（不含 .md），界面自动读取其标题。可附带章节，如 `parent: sandbox-implementations#方案与用法`，兼容已有双链与显示名。阅读面板在顶部工具栏的分类旁显示可点击的上级入口；这条关系同时参与图谱、反向链接与检索校验。parent 不是必填属性，无明确上级时省略，不填列表。目标缺失、锚点缺失、歧义、自引用与循环关系会报告问题。

外部出处推荐填写 `source: "https://…"`，也可用 `source: "[原文标题](https://…)"`；多个出处用字符串列表。兼容 `url` / `URL`，合并去重后在阅读卡片与悬浮预览的标题下方展示；HTTP(S) 链接在新标签页打开，普通出处文本仅显示为文字，无来源时隐藏。复制全文会保留来源，正文无需重复独立的来源行。

支持 Obsidian 双链的文件名、显示名、显式路径、章节与段落块引用，兼容 Markdown 代码与表格中的链接。文档嵌入显示目标摘要与入口，避免递归复制正文。重复文件名阻止索引生成；歧义、断链和缺失锚点显示提示。列表或表格整块的块引用尚未支持。

代码附件放在 `content/assets/`，正文使用 `[[assets/demo.go|完整代码]]`（表格内写 `\|`）。链接沿用内部链接的荧光笔样式。悬停、键盘聚焦或点击链接可预览，点击后保持打开；桌面预览放在阅读面板外侧，侧边不足时在链接段落下方展开并推开正文，避免覆盖阅读内容；支持滚动、高亮、复制和下载，Escape 或关闭按钮退出。代码按需读取，不执行，不成为知识节点，也不设置学习状态。支持 Go、Python、JS/TS、Java、C/C++、Rust、Shell、SQL、JSON、YAML、TOML、CSS、HTML/XML 与纯文本，限 UTF-8、256 KiB；缺失或不可读取时在预览中提示。运行方法和适用条件保留在正文，源文件只存一份。本地与 Pages 共用预览，Pages 仅复制正文引用的合规附件，并以 `.txt` 后缀导出，下载时恢复原文件名。

文档图片与附件只允许读取 `content/` 内 `assets/` 目录的真实文件，支持 PNG、JPEG、GIF、WebP、PDF、MP3、MP4，拒绝越界与外指符号链接。远程图片不自动加载，SVG 附件尚未支持。正文 HTML 显示为文本，不执行脚本。前端代码与素材在应用目录内单独提供。

`npm --prefix apps/web test` 检查文档渲染、引用与锚点、内容安全、附件边界、文件更新，以及三维图谱适配后的关系真实性、分类聚焦和布局边界。`npm --prefix apps/web run build` 检查前端能否构建，产物不包含文档正文；正文仍须本地接口提供。Pages 版本使用同一读取器导出配置中启用目录的全部文档及其引用附件。

重命名文档时需另行维护旧地址映射，目前未自动建立重命名历史。文件读取不突破允许目录，文档内容不作为可执行代码。

## 界面维护与验收

手机端除检查整屏边界，还须在 320px 小屏、常规竖屏与横屏核对工具栏控件不重叠、主要操作具有足够触控面积、列表避开工具栏，以及看板无整体横向溢出。用触屏模式验证搜索聚焦、随机复习和列表切换，并目视检查正文开始位置与实际阅读空间；浏览器模拟不替代真机软键盘和安全区域验证。

本地运行须覆盖 Agent 持续写内容、用户持续阅读、其他 Agent 同时开发的并行情境。内容数据更新与应用代码更新分开：正文按文档和正文块同步，元数据与引用更新相关数据，图谱增删复用画布与镜头；不通过统一重载页面或重播入场来应用内容变化。开发热更新与稳定阅读使用独立服务，构建产物也须隔离。

后台轮询和页面内主动状态切换分别验收。覆盖其他文章修改、当前正文修改及上方插入段落、图表复用、标题与引用变化、文档增删，以及 各启用目录的三态切换和类型、状态筛选开关。检查页面与画布身份、未修改正文块和图表身份、可见段落位置，以及过程中是否重播入场；不能只以最终内容和图标正确作为通过依据。

附件预览沿用内部链接的荧光笔样式，不另造下划线或附加符号；浮层须避开正文，空间不足时改为文内展开。验收同时检查链接样式与预览、正文的矩形边界。

调整主题时先核对 `src/neural/horizon-theme.css` 的当前变量；看板通过 `src/neural/workbench.css` 独立定义石墨色背景与灰绿色操作色，三态色条保持状态语义。外部参考的布局可以借鉴，配色应符合当前项目目标。检查页面外壳、卡片、SVG 图表、热力图、原生控件及交互状态，不能只更换背景；明确要求重新设计时再调整整体视觉方向。

新增统计指标前，先说明数据实际记录了什么、不能证明什么。目录快照变化只能说明检测到文件迁移，不能还原学习过程，不据此恢复「学习状态流转」卡片。先核对指标已有的展示位置，同一统计优先在现有卡片中补充筛选或展开明细，避免多处重复总量与摘要；检测时间和历史覆盖限制沿用「统计看板」的口径。

看板结构入口为 `Workbench.tsx`，分别组合 `DashboardOverview.tsx` 和 `DashboardActivity.tsx`，看板地址由 `dashboard-route.ts` 解析，纯数据口径集中在 `dashboard-data.ts` 与共用的 `activity-model.ts`。看板回归覆盖看板路由刷新与前后退、正文跳转与返回阅读、月历跨月焦点、空态及高度适配。

修改入场或模式切换时，将 WebGL 星点、CPU 投影、SVG 连线、列表端点、标题和阅读面板作为一个整体验收。首次可见机位应按目标布局和恢复的阅读状态确定，入场从目标取景中心展开；依赖场景的 DOM 动画由布局就绪与实际渲染进度驱动，不用固定延迟猜测加载时间。镜头、节点与面板使用协调的过渡进度，不能只检查每个组件单独是否平滑。

首页聚拢球状与阅读舒展、略扁且有纵深的形态分别保留，布局缓存按模式区分。返回首页时，退出中的阅读面板 DOM 不再参与首页取景；动画中反向操作应从当前画面连续衔接。改动相关链路后，在宽屏与窄屏检查首页及阅读刷新、搜索进入、Dashboard 往返、LOGO 返回和动画中反向操作，并核对减少动态效果设置；按影响范围运行已有回归测试与构建，不用测试通过替代整屏目视检查。

## GitHub Pages

GitHub Pages 与本地服务共用 `loadLibrary`，文档来源统一为配置启用目录下的全部 Markdown 文档，兼容递归读取。新增、修改、删除或在已启用目录间移动文档会在下次部署时同步；未启用目录不收录。部署后启用目录的内容都会随站点公开；目录区分知识笔记、面试题、外部导读与术语解释，不表示公开授权，发布前须核对完整导出范围。

```sh
npm --prefix apps/web run build:pages
npm --prefix apps/web run preview:pages
```

静态产物位于 `apps/web/dist-pages/`，包含与本地一致的正文、属性、搜索数据与引用关系，无需本地文档接口。预览地址为 `http://127.0.0.1:4174`。正文引用的有效附件会一并复制并改写为静态地址，沿用本地的附件目录与格式限制。

推送 `main` 后，`.github/workflows/pages.yml` 自动安装依赖、执行类型检查与静态构建，再部署到 Pages。部署流程不运行回归测试，也不等待独立测试工作流；只更新笔记时无需重复安装浏览器和运行交互验收。仓库 Settings → Pages 的 Source 设为 GitHub Actions。发布地址为 [视界](https://lllllan02.github.io/brain/)。页面只读，文档更新仍直接修改源文件。

开发验收使用 `make check`、`make test` 和 `make test-browser`。独立的 `.github/workflows/checks.yml` 在应用、脚本、根包配置、Makefile 或相关工作流变化的 PR 与 `main` 推送中运行格式、类型、单元和接口检查，也可手动触发；仅修改 `content/` 不触发。

完整浏览器回归由 `.github/workflows/browser-checks.yml` 单独运行，仅支持手动触发：在 GitHub Actions 中选择「Check Horizon Browser」→「Run workflow」，选择待验证分支后运行；也可在本地执行 `make test-browser`。界面改动按影响范围完成浏览器验收。测试使用独立样例，不依赖知识库中的固定文章或引用数量；失败时上传 `playwright-results`，保留截图与追踪 7 天。回归测试用于代码变更验收，内容发布只要求构建成功。

## 学习与阅读状态

目录区分用途，所有启用目录的文档（包括 Notes、Interviews、Readings、Glossary）统一使用 `learning_status: pending | reading | organized`，分别显示待学习、阅读中、已整理。缺省按待学习显示；旧版 `understood` 和 Readings 的 `read: true` 兼容显示为已整理，显式三态属性优先。字段规则见 [[docs/metadata-and-links|格式规则]]。

本地阅读页工具栏显示当前状态，点击后立即更新显示，保存期间暂时禁用操作；只有写入成功才提示完成，失败时恢复原状态并显示原因。状态接口按版本返回受影响文档，客户端保留其余正文对象。点击依次切换“待学习 → 阅读中 → 已整理 → 待学习”。打开、预览、滚动均不自动推进。“阅读中”列表与统计看板的“接着读”直接筛选 reading 状态，不再维护独立待阅读队列或书签按钮；状态随文件跨浏览器同步。“阅读中”与“接着读”共用按状态变更时间倒序排列的列表，最近切换的排最前；时间保存在 learning_status_changed_at，重新进入阅读中会移到前面，同状态正文编辑不重新排序。旧文缺少时间时使用已有状态活动记录，仍未知则稳定排在末尾，不猜测历史。原浏览器的待阅读记录会在本地页面读取时逐篇迁为阅读中，确认写回后移除对应旧记录；失败或暂缺文档时保留并重试，静态 Pages 不写入文件。保存仅修改当前 Markdown 的 learning_status 及状态变更时间，保留正文、其他属性、路径和正文时间。接口 `/api/documents/state` 校验本地同源请求与版本，通过临时文件替换避免半写入。

正文修改后，已整理退回阅读中；阅读中与待学习保持原状态。Agent 按格式规则在同次写回中更新；本地服务在活动快照检测到正文变化后也会安全写回。标题、其他元数据或纯路径变化不触发；没有历史快照时只建立基线，无法推断此前的正文修改。正文哈希单独保存于活动快照，服务重启后仍可比较；旧快照未分离标题与正文时，仅在标题未变时检测正文变化。记录不可用时保留原记录并提示同步失败，不据此猜测状态。

三种状态的名称、颜色、高亮透明度、端点与星芒修饰统一由 `document-states.config.json` 管理。待学习使用明亮蓝色表示尚未开始，阅读中使用暖黄表示进行中，已整理使用柔和绿色并显示完成勾；内部链接、预览、搜索、列表及星点标签使用同一映射。静态 Pages 保留状态显示与阅读中列表；修改状态仍需本地服务。
