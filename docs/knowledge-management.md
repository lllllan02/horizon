[[AGENTS|AGENTS.md]] 的操作细则。按当前任务读取对应部分；文档格式与链接规范见 [[docs/metadata-and-links|文件名、元数据与链接]]，写作与阅读验收见 [[docs/writing-style|正文写法]]。

用户通过视界或 Obsidian 学习，Agent 负责把获准保存的资料、讨论和反馈整理成可独立阅读的笔记。基本流程是「明确问题 → 检索已有正文 → 判断归属 → 写回与关联修订 → 验收 → 按阅读反馈继续改进」。规则以本项目文档为准；项目 Skill 如需封装，只编排步骤并引用这些规则，不另存一套约束正文。

## 会话定向

按 [[AGENTS#会话定向|会话定向]] 检查工作区和已有候选；同轮已完成的检查复用，不重复执行。

## 回答与写作的依据

涉及事实、技术机制、产品行为、实现与选型的回答，以及文档实质写作，默认先检索和阅读相关材料形成依据，再组织解释或建议；普通技术答疑同样适用，不能先凭印象写结论，再找链接装饰。研究员的参与方式由 [horizon-team](../.agents/skills/horizon-team/SKILL.md) 编排。

- 从用户给出的文档、仓库及本轮已有候选开始；已有库内材料按下节定向检索。针对关键事实和证据缺口核对官方文档、原始论文、维护方仓库、实际源码或运行结果；根据问题选择材料，不为凑数量扩大搜索。只阅读知识库笔记或搜索摘要，不等于核对了其原始依据。
- 实现行为追踪到相关代码和调用路径，说明版本或提交及适用条件；真实效果与性能结论需要对应实测依据。原文没有解释的设计动机、跨来源归纳和自拟建议明确标为推断或建议，不把模型熟悉程度当作事实来源。
- 回答中的关键判断就近给出处链接或实际文件位置；写入文档时按现有来源规则保留依据。简要说明证据缺口，检索失败、材料不足或未实测时保持结论边界，不将“未找到”写成“不存在”，也不把研究员或审查员赞同当作验证。
- 本轮已经阅读且足以支持当前问题、版本和条件未变化的依据直接复用；新增主张或条件变化再补查。用户提供材料的总结、项目规则维护以原材料和当前项目文件为首要依据。纯错字、排版、流程确认或个人偏好讨论可直接处理；涉及新增事实判断时仍须核对。用户明确限制外部检索时沿用其范围，说明依据不足之处。

检索和研究不改变保存授权；普通讨论仍留在对话中。技术机制的具体推演与写作验收沿用 [[docs/writing-style#精简与依据|精简与依据]]，不另生成检索日志或证据台账。

## 检索与候选阅读

先用程序搜索得到候选路径和命中片段，再由 Agent 阅读正文判断。优先用项目只读检索层 `npm --silent --prefix apps/web run retrieve -- query <词...>`（或 `make search q="..."`）：它复用星云的解析逻辑，覆盖 `apps/web/collections.config.json` 中启用的内容目录，返回候选、命中字段与片段，省去逐篇读取和手工解析元数据。检索层不可用或需要精确到行时，回退 Agent 自带的检索工具（基于 ripgrep）或 shell 的 `rg`、`grep -R -n`。搜索只扫描文件，无需把每篇正文交给模型；一次组合主题词、简称、同义词，复用同轮结果完成内容定位、查重与关系维护。

1. 用户指定文件或当前对话已有相关文档时先读这些候选；先结合已有授权与当前任务目的区分普通查询和[[#专题整理的工作方法|专题继续整理]]，不能只凭本轮使用「检索」或问句判为只读。已授权整理中，用户指出当前产物过长、过浅或询问是否拆分，属于对当前工作的修订反馈；在既定范围内判断并完成修改，只有用户明确要求先讨论、仅评估或暂停写入时才停在建议。普通查询不写文件。
2. 未确定候选时，批量检索配置中启用目录的文件名、属性与正文，查询结果标明目录来源。用能区分问题的词，避免只搜「原理」「性能」等宽泛词；不按单一 category 限死范围。
3. 优先查看标题或别名直接匹配、正文回答同一问题的候选，其次看命中章节，再考虑只在标签或引用中提及的文档。命中次数和目录顺序不代表相关度。
4. 先读候选的元数据、核心回答与命中章节；短文可整篇读，长文按行号读取完整相关段落，写入前再核对全文结构与会影响结论的条件。别名可能采用 YAML 多行列表，不能仅靠匹配 `aliases:` 所在行判断是否存在。
5. 找到支持回答或足以确定写入位置的正文，写作时也已按 [[docs/writing-style#独立阅读与引用|库内关联要求]] 核对相关内容后，停止扩大搜索。需要前置解释、冲突依据或影响范围时沿链接补读，不递归遍历整张关系图。
6. 候选不足时，补充上位概念、替代措辞，或在候选中取消命中数限制。启用目录均无合适内容时，按任务需要扩大到已存在的 sources；原文只作来源依据，不直接作为整理笔记覆盖。缺少来源依据时保留待核实说明，不自行补造结论。

以下命令在项目根目录执行，词语和路径按任务替换；文件名检索与内容检索可在同一轮执行：

```sh
# Agent 检索层（推荐，覆盖配置中启用的目录，返回候选、命中字段与片段）
npm --silent --prefix apps/web run retrieve -- query 覆盖索引 回表

# 查名称；保留结果供后续定位和文件名查重（rg 可用时）
rg --files content -g '*.md' | rg -i 'mysql|index|explain'
# 无 rg 时用 find + grep
find content -name '*.md' | grep -iE 'mysql|index|explain'

# 一次搜索知识笔记、待学笔记与外部导读，返回每个文件最多 3 条命中（rg 可用时）
rg -n -i -F -m 3 -e '覆盖索引' -e '回表' -e 'covering index' content/notes content/interviews content/readings content/glossary -g '*.md'
# 无 rg 时用 grep -R
grep -R -n -i -m 3 -E '覆盖索引|回表|covering index' content/notes content/interviews content/readings content/glossary --include='*.md'

# 已定位候选后，按其实际路径读取正文；长文按实际行号取章节
sed -n '1,100p' content/notes/mysql-explain-extra.md
```

`-m 3` 是首轮控制输出的示例，不是候选总数或完整性保证。命中太多时先只取路径，或增加有区分度的词；不要用 `head` 截掉候选后就判断已查全。发现工具输出截断，应缩小单批范围或分批读取。无匹配（`rg` 退出码 1、`grep` 退出码 1）是正常结果；其他非零退出码是执行错误，需处理，不能当作无内容；不存在的可选目录无需搜索。

## 新建授权与自动补充

在已获准的新建文档任务中，可自行补充与当前问题直接相关的依据和概念解释，无需逐篇征求确认：

- **Reading**：可自动检索相关资源，优先复用已有导读；确有新增价值时，阅读原文并将摘要与导读保存到 `content/readings/`，按[来源规则](#来源与巡检)保留出处、条件与必要定位。不能只存网址或搜索摘要，也不为每篇新文档机械配建 Reading。
- **术语文档**：遇到影响理解的基础或重要概念，可查重后补充到 `content/glossary/`，按[术语库边界](metadata-and-links.md#术语库)解释概念本身，并在使用处自然引用；不因出现一个名词就建卡，不扩写成场景方案或实践长文。
- **Note**：新建 `content/notes/` 文档须有用户明确授权，包括知识正文、拆分子文与专题入口。仅要求保存面试题、整理 Reading、补术语或泛称“保存／整理”，不自动包含新建 Note 的授权；不能因问题独立、需要原理链接或内容未成形而自行新建。用户已明确要求整理成知识笔记或授权本轮新建 Note 时，在约定范围内直接完成，不逐篇重问；其余情况优先复用已有文档，确需新 Note 时先在对话中说明具体拟写内容。

自动补充限于当前任务所需，不递归扩成额外专题，也不借 Reading 或术语的名义变相新建 Note。普通讨论、查询或仅评估拆分方案时仍不自动落盘；面试准备讨论中保存参考 Reading 的既有约定按[面试题流程](writing-style.md#面试题)执行。用户明确只读、先讨论或暂停写入时，停止自动补充。既有文档的更新仍沿用当前任务授权。

## 术语回查与链接补充

新建术语文档后，按标题、别名、英文名与常见表述，批量检索启用目录的已有正文，回查不局限于引出术语的那篇文档。复用本轮检索候选，并补齐尚未覆盖的同义表达；索引有数量限制或结果截断时，扩大上限或用 `rg` 补齐候选。

读命中句及上下文，确认确指该概念、术语卡能解释当前位置的问题后，在每篇首次有意义的提及处补内部链接。保留原句和显示文字；已有合适链接时复用，不嵌套链接、不重复链接同一目标，不替换只是同名的其他含义。标题、属性、代码、外链及引用的原文不做机械替换，归档与原始资料不在默认回补范围。不能为消除漏链扩写旧文、改结论、强加 parent 或要求术语卡反向列出使用者。

纯链接补充按[状态与时间规则](metadata-and-links.md#文件名与属性)保留原学习状态及更新时间；如确需实质修改正文，另按当前任务授权处理。验收时读回修改句，核对显示文字、目标与锚点，并运行一次链接巡检。

## 归属判断与写回

读过候选后，按讨论最终收敛的范围提取要记录的问题、结论与澄清，再为每篇确定一个问题并判断写入位置，不能把整段讨论直接归入同一主题文档。重要追问不等于必须单独建卡，但其形成的有效解释、例子与边界应有归属；探索过但已排除的范围不因出现在对话中就重新展开。篇幅与拆分按 [[docs/writing-style|正文写法]] 判断，不为每段话各建一篇。

| 新内容与已有正文的关系 | 操作 |
| --- | --- |
| 回答同一问题，补充条件、解释、证据或修正 | 更新原文对应位置，保留有效内容与出处 |
| 为原问题服务的附属细节、少量引用或简短参考表格 | 留在原篇，必要时增加小节 |
| 回答独立问题，已有材料需要单独展开，候选仅顺带提及 | 先核对[新建授权](#新建授权与自动补充)，再按用途新建并在有意义的提及处连接已有正文；独立成题不自动授权新建 Note |
| 已有正文完整覆盖，没有新增依据或修正 | 不重复写入，向用户指出已有位置 |
| 与旧结论冲突 | 核对适用条件及双方依据，标明争议或过时，不静默覆盖 |
| 明确要求保存的面试题与口述回答 | 放入 interviews，按 [[docs/writing-style#面试题\|面试题写法]] 保存，原理与解释优先复用 notes |
| 供随查的术语解释，主要回答是什么及必要边界 | 放入 glossary，保留来源与适用条件，复用已有同主题解释，学习状态不改变目录归属 |
| 外部文章、教程或视频的摘要与导读 | 放入 readings，记录来源、主要内容及必要定位链接；不复制知识笔记正文 |
| 供其他仓库执行的任务书、交接提示词或一次性交付材料 | 默认作为知识库外的独立交付文件，不因主题相关放入 notes；用户明确要求入库时再判断归属 |
| 用户要求保存，但内容尚未成形或无法确定归属 | 先在对话中说明缺口并确认归属；仅在已明确获准写入 Note 时，才暂存 notes 并标记待学习及待整理或待核实事项 |

新建前，若首轮只查了文件名或属性，补一次配置中启用目录正文的主题词与同义词检索；已经覆盖的检索不重复执行。已有相似候选须读正文后再决定。检索不足或索引故障时不能据此宣称「库内不存在」，应使用文件检索兜底。沿用 `content/` 文件列表核对拟用文件名，遵守 [[docs/metadata-and-links#文件名与属性|文件名与属性]] 的命名规则。

写回前重新核对目标当前内容和工作区已有改动；若其他编辑改变了候选，重新判断合并位置，避免用旧正文覆盖。新建、更新的目录与属性按 [[docs/metadata-and-links|格式与链接规范]] 处理。查询结果引用实际文档，区分库内依据与额外补充。

保存后复用候选和已知引用，仅补搜新概念、被修正的结论及目标链接。新证据改变旧笔记的结论、适用条件或解释时，同步修改实质受影响的位置，不能只在新文中补链接；无实质影响的旧文保持不变。读回差异，对照获准保存的问题检查是否有遗漏或仅剩空泛结论，再检查原意、出处、重复、属性及链接目标与锚点，并完成 [[docs/writing-style#阅读验收|阅读验收]]；移动、合并或重命名还需维护全部入站引用与附件路径。仅格式或属性调整不刷新 updated_at。完成后简短报告实际文件、修改理由、关系维护与待核实事项，不生成额外操作报告，不自动提交或发布。

## 专题入口与阅读组织

每个已建立的专题都应有自己的独立入口文件（index／目录），统领本专题的文档；知识专题与面试题专题均适用。已有总览能承担时直接作为入口，否则建立简短目录。入口简要交代专题范围，链接各个独立文档；独立文档一个文档回答一个问题，围绕该问题保留必要的定义、原因、例子与边界。专题目录可以按分支或阅读顺序列出链接，不复制各篇答案，也不把多个问题的详细解答集中在入口。单个术语或尚未组成专题的独立问题不机械增建目录，未形成内容的分支不建空入口。文件名与属性见 [[docs/metadata-and-links#专题入口文件|专题入口文件]]。

以个人经历或成果为对象的项目介绍、口述稿和实践复盘，统一由 [[content/interviews/personal-output-index|个人产出]] 入口管理，正文的 `parent` 指向该入口，入口列全直接所属内容。其他专题可通过正文链接引用，不另建内容重复的归属入口；不能只添加入口链接而保留不一致的 `parent`。正文仍按用途保存，调整归属时同步维护受影响入口、引用与管理规则。

面试题统一由 [[content/interviews/interview-hub|面试题总入口]] 承接，按题目积累逐步分层：

- 新增普通题目尚无对应专题时，默认直接收录到总入口，并以总入口为 parent；已有合适专题时直接纳入该专题，不在总入口重复列题。
- 同类题目逐渐增多、需要集中浏览时，再整理为专题子入口，不为单题预建专题，也不设固定题数门槛。子入口列全本组题目并以总入口为 parent，各题的 parent 改为该子入口。
- 形成专题后，总入口用子入口链接替换本组逐题链接，只保留尚未归入专题的单题和各专题入口，避免重复罗列与持续膨胀；更深层的专题沿用同样的分层原则。

先区分「直接所属子文」与「引用的通用概念」：入口覆盖和子文返回要求只适用于前者；后者按 [[docs/metadata-and-links#术语库|术语库边界]] 处理，不因被引用就补 parent、反向链接或应用章节。

编排或缩减一个主题时，先确定用户要达到的程度，再核对该范围内的重要方面，分别决定讲什么、讲多深。结合用户问题、已有正文与必要的权威总览检查定位、组成、使用或实现、适用限制及失败边界；权限等方面是否重要由主题决定，不套固定目录，也不照搬官方全部章节。普通单点补充只检查受影响分支，不重新规划整个主题。

写入前为重要问题确定归属：简短解释留在父文，已有展开链接原文，需要独立展开才建子文，获准暂缓的内容在对应位置留具体 TODO。用临时的「问题 → 位置 → 本次深度」对照检查即可，不新增永久清单或空卡。已排除范围不重新纳入；缺少依据的覆盖判断注明待核实，不宣称已穷尽主题。

- 入口须明确列出全部直接所属文档或子专题入口，链接显示名让读者能辨认各篇回答的问题；可使用简短分组列表。已有总览可保留必要的整体解释，并将已有正文链接兼作目录，不重复维护同一组链接，也不要求逐篇写介绍段。
- 已独立建立的子专题同样有自己的入口并列全本组内容，由上级入口链接；尚属同一问题的步骤或简短补充不机械升为子专题。上级无需重复列出全部后代。普通子文只链接理解或使用本篇直接需要的内容，不把上级已组织的权限、调度、异常、恢复等关联文档再列一遍；相关不等于需要重复入口。正文确有解释需要时仍可就地引用，子文自己的直接下级也仍须有入口。
- 按 [[docs/metadata-and-links#元数据|parent 的知识归属标准]] 判断上下级，再填写主要上级文件名，必要时附带章节；不能从引用、拆分来源或阅读路径推定归属，无明确上级时省略。阅读面板在分类旁显示返回导航，不在文末重复添加。横向前置、比较与延伸链接继续保留，但不是发现同组其他文章的唯一路径；跨专题引用不自动成为本组必读。
- 新增、拆分、合并、重命名或归档时，同步维护所属入口及必要上级入口。入口与正文仍分别只维护一份，不复制全文，不以标签聚合或任意路径可达充当覆盖。
- 重要分支应能从入口的标题或简短介绍中明确识别，不能只埋在「常见问题」等笼统条目的一句话中。树状层级组织问题归属，横向链接补充关系；不按术语数量机械分层。外部导读随对应问题引出，不另建一套脱离主题的资料目录。

验收受影响范围：对照修改前的重要问题及本次新增内容，逐项确认仍有解释、有效链接或获准暂缓的标记；用户明确排除的内容按新范围处理。从入口能直接看全本组，从子文能返回，分支有独立范围且无漏项、失效链接和重复正文。「曾经提到」或链接有效不能代替内容覆盖；压缩、降低深度后尤其要检查重要分支是否消失或被泛化。入口变长时按子专题分层，保留完整覆盖；规则生效不等于历史专题已全部整理，全面补齐需按授权范围执行。

## 专题整理的工作方法

**围绕要理解的问题，先建立整体认识，再逐个讲清分支，最后回到入口收束。** 整理的结果应帮助读者解释机制与取舍，而不只是拥有一组资料。这套方法用于持续整理专题；单篇补充只执行有关步骤，不每次重跑完整流程。

确定问题时，先判断学习者目前哪里不明白、读完应增加什么理解，再决定查什么、写什么、写多深。概念与技术文档都从学习角度剖析：它是什么，为什么需要或为什么成立，怎样运作，与已知内容有什么联系和区别。按当前问题选择必要解释，不机械凑成固定章节；用途、面试或实践场景帮助确定切入点，不能代替对背后内容的理解。沿用上下文中已明确的目标与深度，不因追求深入擅自扩大范围。

整理时把理解缺口落实到正文：陌生概念补必要前置，结论补原因，流程补关键机制，关联补具体关系。例如说明两个概念是依赖、组成、替代还是互补，并解释这种关系为什么成立，不能只添加双链。收尾时检查正文是否足以让读者解释本篇问题、辨别容易混淆的概念，并接上已有知识；篇数、字数、表格齐全、工具运行或代码可用都不能单独证明这一点，也不能据此认定用户已经掌握。

持续整理任务中，用户要求对当前分支继续检索、补充或探索，包括检查哪些内容还值得展开时，应结合已有写入授权完成资料阅读、Reading 整理、归属判断、写回和入口维护，不退回仅在聊天中列建议。重要且需独立展开的内容建卡，同一问题的解释补原篇；普通查询、明确只讨论或只读的请求仍不自动保存。优化话题的检索与交付须包含可用解决办法、所减少的工作及适用边界，不能停在问题与慢的原因。

| 阶段 | 关键动作 | 本轮完成的判断 |
| --- | --- | --- |
| 确定问题 | 从学习者的理解缺口确定要回答的问题、必要前置、范围与深度；大专题按下节先约定边界 | 知道读完应增加什么理解、哪些暂不展开 |
| 查找依据 | 对每个实际展开的子问题先读库内候选，复用足以支持它的 Reading；技术机制按 [[docs/writing-style#精简与依据\|动笔前核对]] 还原原流程，再针对因果缺口核对官方文档、实现或研究及必要的相邻机制，先将新增依据整理进 Reading，再写知识正文 | 每个展开分支的关键因果、事实与适用条件均有依据；专题总览的来源不能自动代替子问题的核对 |
| 形成认识 | 从资料中提取是什么、为什么、如何运作及必要边界，解释与已有知识的联系和区别；按需用具体输入推演过程，优化机制对比同一输入下的原路径与新路径 | 能解释概念、原因与关系，讲机制时能说明问题为何产生、改变什么及哪些约束仍在，再组织正文 |
| 组织正文 | 同一问题合并解释，独立且需要展开的问题才拆篇；详细来源归 Reading，自己的认识写入相应笔记 | 每篇独立可读，正文随解释引出内部链接 |
| 选择表达 | 按解释难点选择文字、表格、JSONL、伪代码或配图，依据 [[docs/writing-style\|正文写法]] 避免重复 | 能看清差异、变化或结构，而不只是多一种展示 |
| 回到入口 | 分支整理后，按最终范围重写总览，提炼分工与联系；细节留在子文 | 入口简洁但覆盖直接子文，不重复来源清单和子文正文 |

外部导读回答「这份资料实际说了什么」，自己的笔记回答「我们怎样理解这个问题」；既不把自己的笔记写成摘要的再摘要，也不把 Reading 精简成只有结论与链接。具体依据优先在解释对应机制的子文中引用，总览只保留支持整体理解所必需的内容。

要求更深入、解释遇到瓶颈或需要验证关键结论时，先找出当前遗漏的专业工作、最直接的材料、适用方法，以及什么结果能支持或推翻判断，再决定补什么。把「扮演专家」落实为具体动作，例如追踪源码调用链、复算原始数据、构造反例或对照实验；工具按证据缺口选择，表格与专业措辞不能替代分析。已有 Reading 足以支撑的解释继续复用；涉及关键因果、争议或效果判断时，按需回到原始论文、实现、日志或数据，并核对版本、采集条件与适用范围，不能只在多份二手总结之间相互印证。

需要跨领域借鉴时，先说明借用的方法解决当前哪个问题、成立需要哪些条件，再执行相应分析；类比只提供线索，不能直接充当证据。从材料中发现新关系或异常信号，先作为假设，再用未参与形成该假设的新样本、其他来源或反例检查；没有发现或验证不足也可收束，不为追求新颖制造结论。

验证方式应对应具体主张：机制判断核对实现与实际行为，数量结论复算数据，性能结论比较同一条件下的基线，结构完整性用链接与元数据检查。Agent 自评或另一轮模型赞同不能代替这些依据，工具通过也只证明其检查范围。探索挑战性目标时，明确基线、约束、成功标准与停止条件；失败后依据新证据调整方法，缺少新线索或达到约定边界时说明限制，不无限重试或降低证据标准。普通概念整理无需为了显得深入而额外搭建实验，未实测的结论按下节标记。

用户指出「太抽象」时，先补具体输入、处理和结果；指出「太长」时，先去重，再判断是否混入独立问题；指出「图没价值」时，检查图是否展示了文字难以表达的变化，而非继续增加方框。修改后复核原先重要信息是否仍在，不能以遗漏换简洁。

每轮依照 [[docs/writing-style#阅读验收|阅读验收]] 与本文件的关系维护要求收束，在约定范围内完成后再推进下一层。删除引用不等于授权删除资料；用户授权清理时，先检查全部入站引用与仍有用途的内容，不能只因总览不再引用就删除 Reading。孤立只是一项检查线索，不是无价值的判断。

### 调研覆盖与未展开内容

调研成文前，围绕用户问题建立临时的「问题 → 所需前置 → 依据 → 正文位置 → 展开程度」对应关系。前置以用户已确认的认识或当前阅读路径实际提供的解释为准，不能因某种做法被称为「传统」「常见」就假定读者掌握。检索既要找到问题与改进，也要找到基本做法如何工作的依据；只找到架构概述或缺陷分析时，基础机制仍是证据缺口。单点补充只核对受影响问题，不生成固定报告或全领域清单。

每个重要问题明确归入以下情况，再决定是否继续检索、写作或标记：

| 情况 | 处理与交付 |
| --- | --- |
| 当前层已经讲清 | 正文能解释基本做法及必要边界；依据在 Reading 或对应原文中可追溯 |
| 理解当前结论所必需，却没有解释 | 在本轮补齐正文或已有解释链接；不能用「待展开」替代基础，也不能默认推迟给用户 |
| 已定位但超出本轮深度，尚需继续展开 | 在相关段落就地写 `**待展开：** 具体问题；目前只讲到什么，下一步需要解释什么`；已有承接文档时链接它，不建空卡 |
| 事实、因果或版本依据不足 | 写 `**待核实：** 不确定的判断与缺少的证据`，保留限定，不能以确定结论带入后文 |
| 实现或效果尚未验证 | 写明未实测的对象与验证缺口；有解释或伪代码不等于实现已验证 |

「待展开」记录正文的知识覆盖，不表示用户尚未掌握；`learning_status` 不能替代它。标记应描述未解决的知识问题，不记录编辑流水，不只写「以后深入」或罗列名词。跨多篇的重要分支在入口的对应介绍处也应看得出当前深度；具体未决问题保留在最直接的正文位置，避免维护两份相同清单。已明确排除的内容不列为待办，不为了显得完整制造未知分支。

收尾时回查问题与正文的对应关系，并按[[docs/writing-style#阅读验收|阅读验收]]实际复述处理过程。子文存在、引用有效、来源数量足够都不等于问题已回答。交付应区分本轮完成范围与仍未展开、待核实的部分；后续补齐解释或证据时，就地移除或改写相应标记，不能让过时 TODO 长期保留。必要依据受阻时可以交付已完成部分，但须明确未完成范围，不宣称专题已完整整理。

## 大专题的分层推进

适用于「整理 Kafka」「系统梳理数据库」等跨多个独立问题的请求。一个明确的单点问题、指定卡片的小改动或已约定范围的后续工作，不重新启动范围访谈。

范围与深度未明确时，先用少量问题确认：用于入门、面试、项目应用还是排障；关注和排除哪些方面；需要理解机制、会用 API，还是深入源码与实验；本轮先做到哪一层。问题可给少量具体选项并说明建议，已有答案不重问。等待期间可以做定向检索和范围盘点，不展开尚未确认的分支，不替用户作出深度选择。

按以下节奏推进，具体层数随主题调整：

1. **确定本轮范围。** 结合现有材料提出少量主要问题，区分本轮展开、仅作定位和暂不涉及；明确达到什么程度就收束。范围约定放在对话中，只有用户要求记录时才持久化，不新建空卡或常驻进度清单。
2. **先形成可读的整体认识。** 讲清专题是什么、解决什么问题、主要组成怎样关联；已有入口就更新它，不另建同义目录。初次不为所有可能分支批量建卡。
3. **逐层展开选定分支。** 在本轮约定内检索、核对来源，按 [[docs/writing-style|正文写法]] 先呈现当前层的简短认识与待展开问题，再完成保存和链接验收。进入子专题后仍沿用这一节奏，由用户选择继续深入的问题；独立且已有足够内容的问题才拆篇，不提前铺开下层配置、源码、调优或运维细节。
4. **本轮完成后再选择下一层。** 简短说明当前层已整理的内容及可继续探索的问题，等待用户选择；当前文件写完不代表专题学习收尾。只有用户明确决定不再深入当前分支或专题时，才按该范围收尾，不由 Agent 自行判定“已经够了”。用户确认当前知识点已清楚、应作为最终叶子卡片，也属于该范围的收尾决定；此时按正文写法保留完整结论，停止预设下层追问，不再机械推荐继续拆分。等待选择时不自动递归展开；用户明确授权连续处理若干分支时按该约定执行，无需逐篇确认。

「合适程度」以约定问题是否得到解释、依据是否充分、必要边界是否保留及入口是否可读为准，不以卡片数量、字数或官方目录覆盖率为准。分层是阅读与工作节奏，不等于必须建更多目录层级。每轮只需覆盖约定范围与已有直接子文，不把「入口完整」误解成提前穷尽整个领域；用户要求深入某个具体问题时可以直接进入该层。

## 修改操作

归属与拆分依据见 [[#归属判断与写回|归属标准]] 和 [[docs/writing-style|正文写法]]。合并、拆分、重命名、移动、归档的操作步骤及验收统一维护在 [knowledge-maintain](../.agents/skills/knowledge-maintain/SKILL.md#修改操作)；先查全部入站引用，完成后维护链接、专题入口与附件路径。

## 冲突与结论维护

区分事实、个人理解、推导与实测，保留关键来源与适用条件。新信息与旧结论冲突时，先核对双方的适用条件、时间与依据，不因来源较新就自动覆盖。需要保留争议时，在原结论处用统一标注记录，便于检索与复核：

```markdown
> **争议**：新结论……；旧结论在其适用条件（……）下仍成立。依据：……。
```

被新来源取代的旧结论用 `> **过时**：……（由 [[新文档]] 取代）` 标注，保留结论与出处，不静默删除历史。跨文档的冲突在双方各自标注并互相链接。未执行或未核实的结论注明「待核实」，不写成既定事实。

## 查询与答案归档

用户查询库内内容时先检索再回答，引用实际文档并给出文件名，明确区分「库内结论」与「额外补充」；库内没有依据时说明检索范围与结果，不用记忆冒充库内内容。普通查询不写文件。

答案是对比、综合或可复用的新结论时，Agent 可主动提议保存；用户要求保存后，同样按归属规则处理：回答已有问题就更新原文，形成需要独立展开的问题才新建，已完整覆盖则指出已有位置。引用库内文档时直接链接，不复制被引正文，不因内容来自问答就固定新建归档页。

## 学习反馈与修订

知识库保存、补充或整理完成后，在简短汇报之后，结合本次实际改动与用户反馈，主动提出一两个值得关注的问题；一个学习问题讨论告一段落时也可采用同样方式。按前置知识、当前理解与掌握、适用边界、延伸问题检查，优先提示影响当前理解的缺口，其次才是延伸方向，不必凑齐所有维度。问题应具体，并用一句话说明它为何值得关注；已有笔记能回答时，可直接指向对应内容。用户明确把某个实现问题留待后续并要求记录，或已授权调研整理中仍有未展开的重要问题时，按[[#调研覆盖与未展开内容|覆盖标记规则]]在相关卡片保留具体问题，优先链接已有专题，不另建空卡或提前展开。没有明确价值时省略，不在每次回复后机械追加。

主动提出的学习提示呈现在对话中，不作为每张卡片的固定栏目，不自动创建卡片、扩写正文或添加学习属性；已授权整理的正文缺口按覆盖标记规则处理。用户决定继续、跳过或暂放，当前对话中避免重复提醒已讨论或暂放的问题；提出理解检查不等于认定用户尚未掌握，也不自动开始测验。需要跨会话保留学习进度时，仍按用户的保存要求处理。讨论后的内容依普通归属规则判断：本篇必需的解释或条件在获准后补原文，个人尚未掌握时先讲解，独立延伸问题在用户要求保存后再决定是否新建。

用户说「看不懂」时，先结合正在阅读的段落定位缺口：缺少前置就补最小解释或已有链接；解释跳步就补因果与例子；拆分过细就评估合并或恢复必要上下文。先回应当前疑问；仅在用户要求保存、修改，或已有对应编辑授权时写回，不把每次追问都变成新笔记。已有编辑授权时，针对当前成品的简化、优化反馈属于继续修改的指导；范围明确且可逆就直接落实并验收，不只给方案等待再次发令。面试题口述练习的纠正与保存时机按 [[docs/writing-style#面试题|面试题准备流程]] 执行。连续收到同一文档的反馈时，先还原用户最终要理解的问题、已确认的范围与呈现要求，再检查现有章节能否承接；按最终认识合并或重写，不按对话轮次累加段落。收尾对照这些要求验收整篇及关联子文，避免只修最近指出的局部问题；具体写法见 [[docs/writing-style#精简与依据|精简与依据]]。明确只讨论方案时保持只读。除上述面试题准备流程外，新建卡片或首次回答遵循先简后补：先用一句话或一段话说清问题，条件、因果、例子和来源等细节在追问下就地补充，避免一次写满，也避免把追问默认当成新卡片。

用户要求安排学习顺序时，先整体定位、再主要组成、后局部机制；按 [[#专题入口与阅读组织|专题入口]]保留阅读顺序及完整范围，细节复用已有正文，不复制答案或另存一套全文。用户要求深入或跳过时按其意图调整，不以固定顺序阻止继续。需要保存进度时，只记录实际阅读或讲解范围、用户提出的疑问及下一步，按普通保存规则归属；文档状态、事实可信度与个人掌握程度分别处理，不从阅读、讲解或整理完成推断掌握。状态字段与确认范围按 [[docs/metadata-and-links#文件名与属性|状态规则]]；理解本篇无需递归学完所有链接目标。

视界的「今日复习」只针对当前已整理资料，独立记录反馈与下次时间；复习操作不改变阅读／整理状态，打开、跳过和退出不算完成。入口、调度与本机／浏览器保存边界见 [[apps/web/README#间隔复习|间隔复习说明]]。用户需要复习提示时，围绕选定内容提出明确、聚焦的问题，并定位到原文答案；不复制完整答案，不默认给全库生成题库、评分或新增学习字段。讲解与测验按用户请求分别处理。

根据用户反馈在授权范围内修订具体内容；明确长期偏好和有充分依据的重复习惯按 [[docs/agent-rules#规则维护|反馈落实细则]] 及时更新对应规则。不因单篇例外增加全库必填字段或自动展开全面改写。

## 索引的现状与维护边界

`scripts/retrieve.ts` 是供 Agent 使用的只读检索层，复用 [[apps/web/README|文档阅读页面]] 的解析逻辑（frontmatter、双链、锚点、反链），覆盖 `apps/web/collections.config.json` 中启用的内容目录，收录范围跟随 `apps/web/collections.config.json` 的启用项；每次按当前源文件实时生成、不落地缓存，因此不会与正文不一致。子命令：`index` 输出每篇一行的 JSON（不含正文），`query` 返回紧凑候选，`links` 查出入链与断链，`lint` 做结构巡检；它依赖 `apps/web` 的依赖，首次使用前执行 `make install`。

正文仍是唯一内容来源，检索层是可重建的派生视图，不另建与检索数据重复的全库文件清单；供人阅读的专题入口按 [[#专题入口与阅读组织|入口规则]]维护，检索派生视图本身不进入公开发布范围。读取候选和写回始终以当前源文件为准，不能仅凭检索层零命中决定新建；规模明显增大后，再考虑落地持久索引或全文引擎。

## 来源与巡检

外部资料检索与收录前先读[来源排除记录](source-exclusions.md)，筛选结果时按 URL 与帖子标识核对；同一帖子的移动版、分享链接或仅跟踪参数不同的 URL 视为同一来源，命中后跳过，不重新推荐或加入待整理清单。用户要求删除或排除的来源，以及整理时决定不再收录的来源，同次保留标题、原链接、排除原因与记录日期；用户明确要求彻底删除链接、不留记录时遵从。历史回补依据当前差异与 Git 历史，未留存的原因和原删除日期注明未知，不推测为质量差；合并重复链接、迁移引用等维护动作不自动视为来源排除。只有用户明确要求重新评估或恢复时才重新处理，并同步更新排除记录。

后续检索与补充面经时，优先选择社招面经，校招与实习面经仅作补充。面经收录以能提取并用于学习的真实面试题为前提。收录前须阅读正文，确认有具体题目可整理；只有求职过程、面试结果、情绪感想或泛泛建议，没有可复用题目的帖子不保存，也不作为待整理链接留在面经清单中。零散提及考点、却不足以还原具体问题，同样不构成收录价值，不能只凭标题、岗位或公司名收录。

在符合上述条件的面经中，尽量优先选择同时提供具体问题、回答框架和作者自身反思的记录，便于学习答题思路、理解回答不足与改进方向。这是选材偏好，不将三项齐全设为收录门槛。

内容用途与状态按 [[docs/metadata-and-links#文件名与属性|目录与属性]] 区分，不生成重复原文、数据库快照或迁移备份。知识库正文（notes、interviews、glossary）中的外部链接，均须先转换为 Reading，再添加内部引用；面试题同样适用，不直接附外部依据链接：先查找已有 Reading；没有合适导读时，在 `content/readings/` 总结与当前问题相关的原文观点、机制、证据和边界，再把笔记中的引用换成指向导读对应章节的内部链接，避免下次使用同一依据时重复阅读外部原文。原始外链保留在 Reading 的 source 与正文定位处；已有导读需确认覆盖本次引用内容，不足时补充或另建适当范围的导读，不能只建含网址的占位页；同一问题下高度重叠的来源可合并，不为每个 URL 单独建卡。无法读取原文时明确标注尚未总结并保留待核实出处，不能用空摘要冒充已完成的导读。总结应让读者无需重读原文，就能复述核心观点、关键机制、设计取舍及其形成过程，并理解必要的例子、证据与适用边界。

总结开篇用一句或一段概括原文核心观点及必要限定，随后展开重要内容；只读开篇也不应形成错误判断，影响结论成立的条件不能只放在后文。原文以数据支撑结论时保留关键数据及比较条件，不能只剩“更快”“效果更好”；原文没有量化时不自行补数字。概括不替代论证，节选或提取不完整时说明实际覆盖范围。仅提取原文或转录时不强加总结结构。

Reading 保存原文的阅读价值，不套用概念卡或入口的压缩尺度：先辨认原文的重要问题与论证主线，再保留支撑结论的失败现象、方案演变、关键机制、验证结果和限制，按原文实际内容取舍，不强制凑齐栏目。删减重复、修辞和旁支，不把有价值的推导压成一句结论，也不以「见原文」替代摘要应说明的内容。篇幅由信息量决定，不统一字数、段数或模板；只摘取某个主题时明确节选范围，不能冒充整篇总结。

保留原链接与必要的章节或源码定位，不复制全文。验收时对照原文检查重要内容是否有归属，以及读者能否说明「作者为什么这样判断、方案如何工作、依据与限制是什么」。逐项回查保留的数字、条件与关键判断，确认比较对象和含义未变；说明资料的实际意义或提出建议时，核对其是否由原文支持，额外推导须区分，不能扩大原文的适用人群与条件。

按内容来源判断归属：主要在整理外部文章、产品文档或源码的内容属于 readings，不限于 DeepWiki，也不因写在 notes 就变成自己的结论。自己的设计与理解留在 notes 知识卡片，不填 `source`、`url` 等来源元数据，也不单列来源段；正文中的外部资料统一通过 Reading 内部引用，具体原文定位保留在 Reading，不在普通知识文档中另附外链。外部导读才记录整篇来源；不是每个链接都必须单独建卡，同一问题下高度重叠的来源可合并总结，优先保留有不同参考价值的材料。读完不自动迁入 notes。

`content/sources/` 收窄为需要保留的原始资料或格式转换内容：例如无法仅靠链接复现的附件、可能失效的页面，以及需要转换以便检索的 Word、PDF 等文件。记录出处、保存时间和版本；转换保留原件及对应关系，原文不覆盖为总结稿。图片等附件按需存入 assets。

原文值得保留的情况：页面可能删除或改写；需要固定引用当时的措辞或数据；本地批注、PDF、付费或离线材料无法仅靠链接复现。Agent 可以提出保存理由，普通引用不自动下载整份原文；保存后与整理笔记区分，不再覆盖为总结稿。

冲突结论说明双方依据与条件，不因来源较新就自动覆盖旧结论。实践卡保留环境、步骤和结果，个人想法不强制改写为知识卡。

专题巡检的范围、检查清单与修正流程统一维护在 [knowledge-maintain](../.agents/skills/knowledge-maintain/SKILL.md#专题巡检)。只要求检查时保持只读；要求整理时修复获准范围内可确定的问题。结构检查不代替事实判断，日常保存不扩大为全库巡检。

## 发布边界

内容默认私人，公开发布须明确授权具体文件；授权文件清单的过滤先于搜索、关系与附件生成，不依赖文档里的可见性字段。

当前实现边界：Pages 导出 `apps/web/collections.config.json` 中启用目录的全部文档，尚未实现上述授权过滤。保存笔记不包含公开授权；过滤实现前，只有完整导出范围均获授权才可发布，否则先实现过滤。构建、搜索、关系和附件须使用同一授权范围，不能只在页面上隐藏未授权内容。
