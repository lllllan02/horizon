[[docs/knowledge-management|知识库管理细则]] 的格式与链接规范。

## 文件名与属性

目录只区分内容用途：notes 保存自己的知识笔记，interviews 保存面试题与口述回答，readings 保存外部资料的摘要与导读，glossary 保存随查术语解释，sources 保存必要的原始资料，archive 保存当前归档的文档（不参与看板）。各内容目录平铺，不用物理子目录表达专题层次或学习状态。文档类型通过 type（兼容已有 classes）区分，主题归属通过单值 category 表达，tags 用于多标签检索。面试题的正文格式见 [[docs/writing-style#面试题|面试题写法]]。

所有启用目录的文档（包括 notes、interviews、readings 与 glossary）统一使用 `learning_status`：`pending`（待学习）→ `reading`（阅读中）→ `organized`（已整理）。新建填 pending，缺省也按 pending 显示。状态由用户主动确认，打开、预览、滚动或 Agent 完成整理均不自动推进；“已整理”不代表掌握全部知识或读过全部外部原文。阅读中列表直接筛选 `learning_status: reading`，不额外添加“待阅读”标签或维护浏览器队列。仅修改状态时不移动文件、不刷新 created_at 或 updated_at。

实际切换学习状态时，同次写入 `learning_status_changed_at`，固定使用北京时间，写为 `YYYY-MM-DD HH:mm:ss.SSS`，保留毫秒以区分快速操作。重复设置相同状态不刷新此时间；仅编辑仍为阅读中的正文，也不改变其排序时间。阅读中列表按最近一次切换状态的时间倒序显示，最近切入的排最前；缺少该属性的旧文优先使用已有“切换到阅读中”的活动记录，均缺失时稳定排在有时间记录的文档之后，不以正文更新时间或文件修改时间推测。

只有正文发生实质修订、需要重新阅读时，才在同次写回中将已整理降为阅读中；阅读中与待学习保持原状态。实质修订包括改变核心结论、适用条件或重要解释，增删主要内容、关键示例，或明显重组阅读结构；按语义影响判断，不按改动字数机械划线，改变关键判断的短句也可能属于实质修订。

仅补充、修正或替换内部链接，调整链接显示文字、格式、标点、错字，或不改变原意的少量润色，均保留原学习状态、`learning_status_changed_at` 与 `updated_at`。链接变化若同时改变重要解释或结论，仍按实质修订处理。仅改元数据或仅移动、重命名文件且正文未实质改变时也不降级；重新标为已整理仍由用户确认。

实质修订同步更新 `updated_at`，作为本地服务识别需要重新阅读的更新标记；服务结合正文快照检测，只在更新时间推进且正文变化时安全写回降级，不凭任意正文差异推断改动大小。外部编辑器中的实质修订也应更新该字段；缺少历史更新时间或快照时先建立基线，不猜测降级。管理文档不新增学习状态。

兼容旧文：`learning_status: understood` 与 readings 的 `read: true` 显示为已整理，`read: false` 或缺省为待学习；显式的三态属性优先。后续状态写回统一使用 `learning_status`，不新增独立的“已整理”布尔字段，也不将该字段写成布尔值。

网站与检索收录范围由 `apps/web/collections.config.json` 的启用项决定，默认 notes、interviews、readings、glossary；目录来自路径，学习状态来自元数据。状态外观配置在 `apps/web/document-states.config.json`，交互见 [[apps/web/README|视界说明]]。常规补充保持路径稳定，重构改变主题范围时按命名规则同步改名并维护引用。

文件名使用简短英文与短横线，如 `agent-definition.md`、`mysql-explain-type.md`。在 content 内的笔记中保持唯一，包括 notes、interviews、readings 与 glossary；只在实际冲突时加必要的限定词，不把完整分类层级拼进名称。文件名按内容适当收敛：主题能被更短、更上位的词涵盖时就用它，避免「主题 + 动作/限定」的冗余（如 OAuth 授权 → `oauth`）。README.md、AGENTS.md 等项目约定名称保留。

内容收敛、拆分或重构后，文件名应跟随最终主题调整，不能只改 title 而沿用已不匹配的旧文件名。例如，`trace-and-span.md` 收敛为只解释 Trace、Span 已独立成篇时，应改为 `trace.md`。先核对新文件名在 content 中唯一，再按重命名流程维护全部引用；仅因措辞偏好或普通补充不反复改名，重命名也不改变元数据中的学习状态。

## 专题入口文件

专题入口（index／目录）仍是普通 Markdown 文档，按所属用途平铺保存：知识专题放在 `content/notes/`，面试题专题放在 `content/interviews/`。新建纯目录可使用 `<topic>-index.md`，如 `go-interview-index.md`；标题使用「主题名」或「主题名目录」，`type: overview`。沿用统一时间与学习状态规则。

已有总览承担入口时保留原路径，不再创建同主题目录副本。文件名在整个 `content/` 内保持唯一，不在各专题重复使用裸名 `index.md`。单题或单问题文档有明确专题归属时，以该入口为 `parent`；跨专题通用概念仍用正文引用关联。入口覆盖与维护按 [[docs/knowledge-management#专题入口与阅读组织|专题入口规则]] 执行。

## 术语库

`content/glossary/` 平铺供随查的术语解释，主要回答概念本身「是什么、有什么边界」。通常用简短定义、必要例子、易混边界与出处讲清，不机械套栏目，也不因提到术语就建卡。

每篇围绕一个可独立定义的术语；含义与职责不同、可分别查阅的概念分别成篇，不因经常配合使用或各自篇幅短而合并。同义名称与同一概念的简短变体可在一篇解释；概念间的配合与区别用必要的简短说明和正文链接表达，不要求读者跳转后才能理解当前术语。

正文独立于遇到该术语的话题：具体协议或项目怎样使用它，写在对应话题或实践卡片中，由使用处引用术语卡；不为返回原话题而添加应用章节或链接。术语卡只在解释自身确有需要时引用其他概念。具体话题首次使用术语时可保留使原句可读的简短释义，完整定义和通用例子集中在术语卡，场景约定留在使用处。例如 Stdio 卡解释标准流；MCP 如何通过标准流传输消息、日志如何处理，归 MCP 或其实现卡片。

术语卡沿用统一的学习状态；内容稳定程度不是分类依据，涉及版本仍需注明。

以具体外部资料为对象的摘要放 readings；需要理解机制、作出判断或完成实践的问题放 notes。已有同主题内容先判断归属并复用，不在不同目录复制定义。术语可被多个专题引用，不因被 MCP 使用就强设 MCP 为 parent；有清晰概念上级时沿用 parent 规则。Glossary 与其他收录目录共享文件名唯一、来源、链接及发布约束。

## 元数据

文档元数据使用 YAML frontmatter。以下字段按需使用，不要求每篇填齐，也不生成空字段或空列表；有用途且值可靠时再填。文档标题放在 title，保留中文或正式技术名称，并按 [[docs/writing-style|正文写法]] 使用简短概念名或准确主题名，避免把引用处的引导问题写成概念篇标题；正文直接从核心内容开始，不使用一级标题，需要分节时从二级标题开始。

| 字段 | 用途与写法 | 何时使用 |
| --- | --- | --- |
| `title` | 正式标题，文本，正文不重复添加标题 | 有正式标题的文档保留，供看板展示中文标题 |
| `aliases` | 其他名称、简称、同义词或英文名，列表，如 `["执行计划", "MySQL 执行计划", "EXPLAIN"]` | 有实际检索或链接补全价值时使用；中文标题可补英文名、通用缩写，方便英文检索，避免宽泛或机械生成的别名 |
| `category` | 唯一分类，自定义文本属性，如 `"MySQL"`、`"RAG"` | 看板按此字段动态生成星云；每篇只填一个名称，缺失或空白显示为「未分类」 |
| `parent` | 知识归属上的主要上级，直接写文件名（不含 .md），如 `parent: agent-sandbox` | 概念或专题范围存在明确包含关系时填写；不表示来源或跳转路径，无明确上级时省略，不填列表；显示在分类旁边 |
| `tags` | 多标签列表，如 `["索引", "SQL优化"]`，复用已有命名 | 需要检索、筛选或跨主题关联时使用，新增前先检索现有 tags 是否已有同义项，不决定星云归属 |
| `created_at` | 原文创建时间，固定使用北京时间，写为 `YYYY-MM-DD HH:mm:ss`，如 `2026-10-21 15:30:00` | 新文记录；创建后不变，旧文未知时省略 |
| `updated_at` | 正文最后实质变更时间，格式同上 | 新文及实质更新时记录；格式、属性名或路径变化不刷新 |
| `type` / `classes` | 文档类型；新文优先单值 type，如 `concept`、`practice`、`article`、`overview`；已有 classes 是类型列表 | 有分类需求时使用，同一文档不重复维护两者 |
| `description` | 一句话摘要，文本 | 正文开头不足以支持预览或展示时使用，避免重复维护同一摘要 |
| `source` / `url` | 外部出处；推荐 `source: "https://…"`，可写 `source: "[原文标题](https://…)"`，多个来源使用字符串列表；兼容出处文本及 `url` / `URL` | 仅 readings 外部导读填写；notes 不填 `source` 或用 `url` / `URL` 替代。来源在标题下展示，必要的正文引用仍可保留 |
| `learning_status` | `pending`（待学习）、`reading`（阅读中）、`organized`（已整理） | 所有启用目录共用，新建填 pending；用户主动推进状态，正文修改按上文降级 |
| `learning_status_changed_at` | 最近一次实际状态变更时间，北京时间，写为 `YYYY-MM-DD HH:mm:ss.SSS`，保留毫秒 | 切换状态时写入，供阅读中列表排序；不改 created_at 或 updated_at |
| `read` | 旧版 readings 的 YAML 布尔值 | 只为兼容旧文保留，新文和状态操作使用 learning_status |
| `status` | 工作状态，文本，如 `draft`、`review`、`done` | 有实际草稿、核查或处理流程时使用，不作为事实可信度或掌握程度 |
| `cssclasses` | 样式名称列表，用于 Obsidian CSS 片段 | 需要单篇特殊显示样式时使用 |

Obsidian 内置的常规属性是 tags、aliases、cssclasses，其他字段是本项目约定。看板按单值 category 动态生成分类星云；category 为本项目约定的自定义文本属性。type / classes 表达文档类型，cssclasses 用于显示样式，二者分开。[官方属性说明](https://obsidian.md/help/properties)

新文的 created_at 与 updated_at 初始相同，写入时读取当前时间，固定按北京时间记录到秒，并用引号包裹。旧文仅有 `YYYY-MM-DD` 时保留原精度，不补造时分秒；后续实质修改只更新 updated_at，小改动的判断按上文[状态与时间规则](#文件名与属性)。迁移时间不代替原文创建时间，已有更新时间保持不变。适用条件、事实争议与待核实内容仍写在正文；不因支持可选字段而批量补齐旧文，不添加无用途的迁移字段。

时间记录与页面显示统一使用北京时间，不跟随设备或用户所在时区切换。新写入的 `created_at`、`updated_at` 使用带引号的 `YYYY-MM-DD HH:mm:ss`，例如 `created_at: "2026-10-21 15:30:00"`；状态、活动与复习记录仅为区分快速操作保留三位毫秒。日期和时间之间使用空格，不写 `T`、`Z`、时区名称或偏移后缀。文档详情同时展示有效的创建时间与修改时间，即使两者相同也保留各自标签。只有一项时只显示该项，只有日期时保留原精度，无效或未知时间不补造。旧的带偏移或 `T` 分隔时间继续兼容读取，按原有含义转换显示；无偏移的完整时间默认就是北京时间。后续新建和实质更新按新格式写入，不为统一格式批量重写旧文，不因格式转换刷新时间或学习状态。

「最新文档」优先按有效 updated_at 排序，其次 created_at，两者都缺失或无效时回退到文件最后修改时间（mtime）。旧文只有日期且日期相同时，用 mtime 区分先后。mtime 只作为读取时的独立字段，不回填为原文创建或实质更新时间；复制、检出或部署可能改变 mtime，因此兜底排序可能随环境变化。

中文标题宜补充英文名、通用缩写等别名，便于英文检索。aliases 有助于链接补全和发现未链接提及。实际双链仍以唯一英文文件名为目标，如 `[[mysql-explain|执行计划]]`；一次性的显示文字不必加入 aliases。[官方别名说明](https://obsidian.md/help/aliases)

`status: done` 只表示文档处理完成；事实依据与个人学习进度按 [[docs/knowledge-management#学习反馈与修订|学习反馈规则]] 分别记录，不据此推断可信或已掌握。没有实际消费方时，不新增难度、掌握度、复习日期或关系类型等必填属性。

`parent` 表达知识内容的包含关系，例如「专题 → 子问题」「机制 → 实现方案」，不记录文档从哪里拆出、在哪里被提及或读者从哪篇跳入。判断时先问：脱离这次讨论与阅读路径，本文是否仍是上级主题的组成部分？引用、前置概念、比较对象与横向延伸用正文链接表达；某篇比较 A 与 B，不因此成为 A 或 B 概念本身的上级。例如 Workflow 可被「Agent 与 Workflow 的选型」引用，但不应归属于该比较文。没有合适上级时省略 parent，不为返回导航强设归属或新建空入口。

`parent` 默认直接写文件名，界面自动显示目标文档的 title，无需另写显示名。需要定位章节时写 `parent: sandbox-implementations#方案与用法`；兼容已有双链与显示名写法。它参与图谱、反向链接与链接校验；目标、锚点缺失或有歧义，以及自引用、循环关系会报告问题。每篇只选一个主要上级，跨专题关系仍用正文双链；上级入口仍需完整列出直接所属内容。

## 链接与合并

内部用 Obsidian 双链，不加 `.md`，笔记直接引用唯一文件名，如 `[[agent|Agent]]`、`[[mysql-explain|EXPLAIN 总览]]`。不将 notes、interviews、readings 或 glossary 目录写进常规笔记链接，不使用 `/Users/...` 等本机绝对路径。中文用于显示名，外部 URL 使用 Markdown 链接。

解析先匹配 Vault 内的准确路径，再检查路径后缀是否唯一，无法唯一确定则报告歧义，不能随意挑选同名文件。章节用 `[[目标#标题|显示名]]`，块引用用 `[[目标#^block-id]]`，附件用 `![[assets/image.png]]`；目标和锚点必须存在。 Markdown 表格中的双链显示名分隔符须转义为 `\|`，如 `[[intent-clarification\|澄清与回退]]`，避免被解析成新列；验收时检查渲染后的单元格内有完整链接，不能仅凭目标存在或链接检查无报错判断通过。管理文档位于 Vault 外，跨目录链接使用项目根路径。

位图可用 `![[assets/image.png|480]]` 指定正文显示宽度（正整数，单位 px），高度保持原图比例，窄屏最大不超过容器；尺寸选择按[[docs/writing-style#图文分工|图文分工]]。这是显示尺寸，不修改源图像素；视界支持 PNG、JPEG、GIF、WebP 的单独宽度写法，不将 `宽x高` 当作已支持的语法。

代码按[[docs/writing-style#独立阅读与引用|正文阅读负担]]决定是否外置；外置时作为 `content/assets/` 下的源文件保存，用 `[[assets/example.go|完整代码]]` 引用；视界提供代码附件预览、复制和下载。附件不设置笔记元数据、不加入知识图谱，正文保留用途、运行条件与边界。代码格式和大小范围见 [[apps/web/README|视界说明]]；同一实现不再复制到 Markdown 笔记中维护。

### 附件留存

`content/assets/` 最终只保留正文（含归档）、规则或实现实际引用的在用附件，以及这些附件的必要依赖。图片生成与修改的候选图、旧版本、提示词、图源和额外导出文件默认放在临时目录；选定结果后，只把实际使用的文件放入项目，清理失去引用的过程文件。不因成图仍在使用，就自动保留同名提示词、图源或其他格式副本，也不为保留文件补造链接。用户明确要求单独交付或保留的文件按该用途处理。

清理前核对项目中的实际引用和附件依赖；生成提示词、编辑沿革、备份及构建产物中的记录不算在用引用，过程文件之间互相提及也不构成保留理由。修改或删除引用时，同次清理相应的失用附件；不扩大为其他附件目录或独立实验仓库的清理。

### 链接维护

链接所表达的语义与行文方式见 [[docs/writing-style|正文写法]]；专题覆盖及返回路径见 [[docs/knowledge-management#专题入口与阅读组织|专题入口]]。星云连线包含正文引用与 parent，不自动表达学习先后。

合并、拆分、移动、改名或删除时，按 [knowledge-maintain](../.agents/skills/knowledge-maintain/SKILL.md#修改操作) 查询入链并更新目标、显示名及锚点；Agent 直接操作文件不依赖 Obsidian 自动维护。

新建前沿用内容检索，发现文件名冲突时用必要的限定词调整新名称；不为重名新增前置或后置检查脚本。若接手的内容已有同名文件，处理前暂用从 Vault 根开始的完整路径消歧，如 `[[notes/overview|中文标题]]`，不随意选择目标。[Obsidian 设置](https://obsidian.md/help/settings) 中使用最短唯一路径并启用自动更新内部链接；Agent 的文件操作仍须维护受影响的引用。
