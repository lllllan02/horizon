## 范围与依据

遵守项目 [AGENTS.md](../../../AGENTS.md)。保存新讨论仍从 [knowledge-save](../knowledge-save/SKILL.md) 进入，仅在需要改变已有文档结构时使用本技能对应步骤；不要把普通保存扩大成专题或全库巡检。

先明确用户指定的文件、专题和操作，复用本轮工作区检查与候选检索。只要求检查或建议时保持只读；要求整理、修正时完成获准范围内的修改，不重复确认。涉及拆分子文或新增入口时，先核对[新建授权](../../../docs/knowledge-management.md#新建授权与自动补充)，不因结构需要自行新建 Note。归属依据见 [归属判断与写回](../../../docs/knowledge-management.md#归属判断与写回)，个人学习状态见 [学习反馈与修订](../../../docs/knowledge-management.md#学习反馈与修订)，不要从整理完成推断掌握。

## 修改操作

先读清目标全文结构与适用条件。涉及正文重组或阅读困难时，按[面向学习的编排](../../../docs/writing-style.md#面向学习的编排)定位解释断点，判断重排、就地补足或合并是否已能解决，再决定拆分；不要用增加链接代替必要解释。再查全部入站引用：在项目根目录运行 `npm --silent --prefix apps/web run retrieve -- links <文件名>`，记录旧路径到新路径及受影响引用。该工具覆盖 `apps/web/collections.config.json` 中启用的内容目录；目标不在索引范围或检索异常时，用 `rg` 补查实际路径、文件名和锚点，不把「未找到」当作没有入链。

按[专题入口细则](../../../docs/knowledge-management.md#专题入口与阅读组织)先核对重要问题及其归属，修改后逐项对照；压缩和降低深度同样执行覆盖检查，不仅检查文件移动与链接。涉及 parent 时，阅读本文与拟定上级的主题范围，按 [parent 归属标准](../../../docs/metadata-and-links.md#元数据) 重新判断知识包含关系，不从拆分来源自动继承上级，也不因新增引用而改变归属。

- **合并**：两篇回答同一问题时，选内容更完整的一篇为主，吸收另一篇的有效正文与出处；把指向被合并文档的双链按引用意图改指向主文档并保留显示名，确认无残留后删除或移入 archive。
- **拆分**：一篇承载多个需要独立展开的问题时拆成多篇，各篇只留自己的问题与依据，必要的简短原因、对比和参考仍可留在原篇。按 [正文写法](../../../docs/writing-style.md) 维护总领卡片的引导，并把原双链按语义改指向对应文档；既检查目标有效，也检查阅读入口是否仍能找到各部分。
- **重命名**：常规补充保持文件名稳定；内容收敛、拆分或重构后，若旧名已不匹配最终主题，应在本次重构中同步改名。先核对新名唯一，记录旧名到新名及全部入站引用，改名后逐一更新并检查残留、断链与歧义；不因改名自动修改学习状态。
- **移动与归档**：按 [目录与文件名约定](../../../docs/metadata-and-links.md#文件名与属性) 判断目标目录，保留有效正文、出处、原有日期并维护附件路径。内容当前先精简掉但可能恢复时移入 `content/archive/`；不再恢复时按 [链接规则](../../../docs/metadata-and-links.md#链接与合并) 把入站双链降级为普通文字，保留原句语义。

按解析后的目标更新链接，保留显示名与有效锚点；合并和拆分后的旧锚点需按原引用语义重新定位，不能只判断新目标存在。Agent 直接操作文件时自行维护，不假设 Obsidian 已更新。同步检查 [专题入口](../../../docs/knowledge-management.md#专题入口与阅读组织) 的直接所属内容、必要上级入口和子文 parent 返回路径。

以上操作保留原文创建日期；仅格式、属性或路径变化不刷新 updated_at，正文实质修改按 [时间字段约定](../../../docs/metadata-and-links.md#元数据) 处理。有效出处指支持知识内容的参考资料，不要求保留对话来源或编辑沿革；不在卡片中追加拆分、迁移或整理说明。

## 专题巡检

大专题范围或深度未明确时，先按[分层推进细则](../../../docs/knowledge-management.md#大专题的分层推进)确定本轮子范围；分批巡检不等于默认重写整个领域。每批完成当前层的结构与内容验收后再依据用户反馈推进，复用已明确的约定。

用户要求巡视整个模块时，先用 `npm --silent --prefix apps/web run retrieve -- index` 建立范围，结合标题、正文和必要引用补充跨分类候选，再按子专题分批阅读；索引只用于定向，不能替代内容判断。保留检查前的结构问题基线，区分本次新增、范围内既有与范围外问题。普通巡检限于指定范围，全库巡检须有对应请求。

- **断链与歧义**：双链目标或锚点不存在，或多篇同名导致无法唯一解析。
- **重复**：比较每篇回答的问题与适用层次，不能仅凭术语相同判重。总览、通用机制、产品摘要与实现示例可分别保留；相同细则集中到一篇，其他位置简述边界并自然引用。跨领域通用原则归入通用卡片，专题只保留自身差异。
- **入口与归属**：结合 [专题入口细则](../../../docs/knowledge-management.md#专题入口与阅读组织)，先按 [parent 归属标准](../../../docs/metadata-and-links.md#元数据) 复核上下级是否成立，将误作归属的引用、比较或延伸关系恢复为正文链接，无明确上级时移除 parent；再核对父入口是否介绍全部直接子文、子文能否返回、是否存在归属循环；横向引用不替代专题入口，上级无需重复列出全部后代。
- **孤立**：没有任何入站双链，也未被 README 等入口文档提及；仅作为阅读入口缺失的候选，不为消除孤立而强加链接。
- **元数据**：title、category、tags、type 与日期是否合理，日期是否与正文最后实质变更一致。标签专项治理使用 [tag-taxonomy](../tag-taxonomy/SKILL.md)。
- **过时与冲突**：结论已被取代却未标注，或存在无依据的过期内容；按 [冲突维护](../../../docs/knowledge-management.md#冲突与结论维护) 核对双方条件与依据。
- **格式与写作**：是否违反 [格式规则](../../../docs/metadata-and-links.md) 与 [写作规则](../../../docs/writing-style.md)，是否依赖原始聊天、解释跳步或拆分过细。

全库结构巡检可运行 `npm --silent --prefix apps/web run retrieve -- lint`（或 `make lint`）；局部任务只验收受影响范围。工具报告结构问题，不代替事实判断。获准整理时直接修复可确定的范围内链接与格式错误，事实争议先报告；只读检查不写文件。

## 验收与交付

读回差异，确认有效内容与出处保留，文件名匹配主题，旧引用无残留、目标与锚点无断链或歧义，链接仍指向原来要解释的内容。按 [阅读验收](../../../docs/writing-style.md#阅读验收) 检查独立可读性和拆分粒度，并复核受影响的 parent 是否符合知识归属；归属成立后再检查入口覆盖与子文返回，不以双向可达代替语义验收。

简短说明实际文件、关系维护、覆盖范围与待核实事项，不把结构检查通过称为事实或代码验证通过，不生成额外操作报告、不自动提交或发布。学习反馈按管理细则处理，不强加测验或学习属性。
